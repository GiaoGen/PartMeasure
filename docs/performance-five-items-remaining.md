## 1. 五项的口径与当前结论

本页“第五项”指用户后来明确授权的**有边界缓存**。原始方案中的“双端验收”仍是跨项验收门槛，不能因编号变化而删除。

| 项目 | 已交付的基础 | 尚未完成 | 当前判断 |
|---|---|---|---|
| 1. 默认直连与分段诊断 | 默认脚本不继承进程代理；有脱敏 Auth/SQL/Storage/HTTP 计时与协议探针 | 大陆真实物理链路验证；偶发 PostgreSQL 建连故障根因；受控统计基线 | 代码已实现，网络稳定性和大陆效果未验收 |
| 2. 请求与数据库往返减负 | 并发读取合并、CSRF 复用、写响应增量接入、复用现有查询契约 | 冷/热态、并发下的 p50/p95、错误率和字节量对照；必要时依据实际执行计划定位剩余慢点 | 已有真实服务检查，未证明整体时延达标 |
| 3. 事件驱动双端同步 | 事务 outbox、Owner/Guest 游标、SSE、局部失效、追平/撤销；移除正常“刷新任务/交付”入口 | 浏览器实际绘制与未保存输入保护、前后台恢复、长期连接轮换、跨实例容量及稳定性验证 | 六组真实 HTTPS 同步/权限检查曾通过，最新完整流程仍失败 |
| 4. 安全图片快速路径与就近处理 | 方向归一化、320/640 缩略图、懒加载、优先队列、租约与监督、无 Docker 托管包 | 新 Guest 上传全链路失败闭环；常驻主机部署；资源/更新/清理/告警运行验证；旧图补建收尾 | 主要剩余实现与运行缺口集中于本项 |
| 5. 有边界缓存 | 统一数据缓存、事件精准失效、版本化图片预算、会话清理、服务端命中逐次核权 | 最新代码 Preview 部署、真实多标签/手机生命周期、实际内存和节省量验证 | 实现及本地/真实服务自动检查已通过，外部验收未完成 |

目前不能承诺“上传后另一端立即可见”已经稳定实现：事件通道有通过证据，但新文件仍依赖安全处理成功；处理链路与常驻 Worker 尚未闭合。缓存减少重复请求，不能消除首次读取、网络故障或处理排队。

## 2. 必须关闭的失败与运行缺口

### R-01：新上传到另一端可读的完整流程尚未通过（第 3、4 项）

- 实际实验出现 120 秒 `WORKER_TIMEOUT`，查询时目标上传仍 queued、attempts 为 0。这不能归类为图片解码失败，也不能算处理成功。
- 去掉实验附带的旧孤儿清理后仍复现，尚不能把清理认定为根因。
- 实验后来改用单个受监督的常驻 Worker；最后一轮却在准备阶段以 `ASSERTION_OR_DEPENDENCY_FAILED` 结束，未证明改变启动方式解决了超时。
- 独立旧图补建成功、子进程图像测试通过，均不能替代新上传全链路。

**关闭标准**：在明确版本的 HTTPS 测试环境中，正常 Guest 新上传 → 安全扫描 → 归一化/缩略图 → 原子 ready → 事件 → Owner 受控读取全部成功；记录各阶段耗时和失败码。补测部分失败/重试、撤销后完成拒绝，未安全处理的资产始终不可读。先定位失败，不降低扫描、TLS 或权限要求。

证据：[最新完整运行（FAIL）](evidence/performance-s34/live.json)、[有六组通过但上传失败的独立样本](evidence/performance-s34/live-PERF-S34-1792419190508.json)、[第 3、4 项报告](performance-s34.md)。

### R-02：就近常驻 Worker 尚未部署（第 4 项）

已有 Linux systemd 包、租约续约、失败退避和独立 cleanup timer；尚无落实的目标主机、部署权限和成本方案，未在 Linux 云主机安装或完成演练。本机脚本生命周期里的 Worker 不能当作云常驻服务。

**关闭标准**：确定靠近东京 Storage 的受控主机和具体费用，部署受限账号/扫描器/Worker，验证开机恢复、进程退出自动拉起、租约恢复、队列公平性及持续上传时延。缺少资源时列外部条件，不擅自采购，也不将常驻进程塞进限时网页函数。

### R-03：托管资源、安全更新、清理和告警未闭环（第 4 项）

| 未完成项 | 已有基础 | 关闭标准 |
|---|---|---|
| 临时磁盘硬配额与故障隔离 | 子进程限制，unit CPU/内存配置 | 在目标 Linux 主机落实硬磁盘预算；验证 OOM、磁盘满、超时、扫描器失效后停止当前处理、清理临时字节并继续安全处理后续作业。`PrivateTmp` 本身不是磁盘硬配额。 |
| 病毒库持续更新与过期告警 | 本机曾完成更新；监督入口核验新鲜度及实际加载版本 | 托管自动更新/重载可运行；陈旧、更新失败或未加载时停止处理并告警，恢复后再放行，不绕过扫描。 |
| 独立清理持续运行 | cleanup service/timer 包、幂等清理代码 | 验证定时执行、失败重跑、对象删除核实及配额释放；不删除有效历史资产，不重复释放预留。 |
| 指标与告警接收端 | 白名单错误码、作业状态 | 配置实际接收端、阈值和处置步骤；积压、依赖失败、签名陈旧、容量不足能触发脱敏告警。 |

本项对应 [P0 缺口 I-01～I-04](P0-4/06-p0-gaps.md)，包交付不等于条目关闭。运行步骤见 [Worker README](../deploy/worker/README.md)。

### R-04：偶发数据库建连故障根因未确定（第 1～3 项）

SSLRequest 有时得到正常 `S`，有时得到 `08P01` / `Invalid startup message: :bad_startup_payload`。采样发生在证书、密码和 SQL 之前；客户端脱敏分类为 `pg_ssl_request_rejected`。不能据此把问题归咎于 SQL 执行、密码或某个供应商。

开发机 DNS 曾返回 `198.18.0.244` 虚拟/fake-IP 地址。清理子进程代理变量不能证明系统 TUN/VPN/DNS 链路是大陆直连；本轮未修改这些系统设置，也不能推断 Supabase 天生需要代理。

**关闭标准**：分别在已确认链路的开发机与东京测试部署采集成功/失败协议、DNS、建连和请求分段数据，明确故障层及可复现条件；修复后持续采样并报告错误率。禁止关闭证书校验、自动切代理或盲目重发未知结果写入来掩盖失败。

证据：[SSLRequest](evidence/performance-s34/pg-ssl-request.json)、[错误分类](evidence/performance-s34/pg-startup-errors.json)、[连接记录（含失败）](evidence/performance-s34/cloud-connections.json)。

### R-05：旧图缩略图补建尚未全部收尾（第 4、5 项）

真实云旧图补建已有成功记录，未证明所有旧图已处理完。历史聚合曾为 1 ready/19 queued，之后又运行过补建，**该数字不是当前库存**。没有缩略图的旧证据显示准备/不可用状态，并保留受控原尺寸入口；不能伪装已生成。

**关闭标准**：在常驻安全 Worker 上有界回填，记录最终 ready/queued/dead/预留聚合与失败处理；核对原标准图 hash、标注位置和历史引用不变，人工确认缩略图及原尺寸证据可读。此任务不重新压缩或覆盖标准图。

## 5. 下一步顺序与验收边界

1. 先定位 R-04 建连错误与 R-01 新上传失败，避免通过加长超时或反复重试掩盖问题。
2. 落实受控 Worker 主机与具体资源/费用，完成 R-02/R-03，再复测新上传及有界旧图补建 R-05。
3. 将最新代码部署到测试 Preview，进行 V-02～V-05 的目标环境检查；沿用[双端人工清单](performance-s34-manual.md)，不重新建设业务模块。
4. 完成真实大陆手机整站验证 V-01，按实测失败定位后续修复，不预设必须代理或迁移 Supabase。

**阻止当前五项宣称完整达成**：新上传完整回归失败、常驻处理环境缺失、连接稳定性未闭环、流畅度/大陆真机证据缺失。它们不阻止继续前端设计或提交已有代码，但阻止宣称独立持续运行、上传即达或性能目标验收通过。

**待审批/外部条件**：当前没有新增业务交互方案待批准；主机、部署权限、具体费用及告警接收端尚未落实。本页不触发购买资源、发送邮件或生产部署。

**其他P0历史待验另列**：真实新注册数字OTP、P0-4人工、真实附件/手机下载、备份恢复等沿用[P0缺口清单](P0-4/06-p0-gaps.md)。正常密码登录不代替注册OTP；不把这些历史项称为缓存缺失，也不为此提前实施P1/P2。整个P0仍未全部验收。
