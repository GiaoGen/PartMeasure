# 取消常驻 Worker 的上传改造提案

后续：用户明确“开始简化”后，已按轻量作品取舍实施A路径，最新运行方式、检查与限制见[轻量上传实施记录](lightweight-upload.md)。以下“未实施”指提案提交时的历史状态，不再要求另租服务器。

日期：2026-10-20（Asia/Taipei）。**状态：只供审查，未实施、未部署。** 用户已明确要求不再使用独立 Worker；本轮仅提出替代方案，不修改业务代码、数据库、凭据或平台配置，不启动处理进程或采购资源。

## 1. 问题与新的架构边界

PRD §6 的首选部署是 Next.js/Vercel + Supabase，没有强制第三台常驻服务器。独立 Node Worker 与 ClamAV 出现在后续 [ADR-01](P0-0/08-runtime-decisions.md) 文件处理方案中，但托管、费用和持续运行没有落实；因此网页上传完成后仍可能无人处理。这是运行依赖交付缺口。

本次用户要求优先于旧方案：停止将“另租主机并部署 Worker”作为后续必走路径。旧实施记录保留历史，但不能继续据此启动或采购常驻 Worker。**取消独立 Worker 已是明确要求；下面具体替代流程和扫描保障变化仍是提案。**

目标：只部署现有网站与 Supabase；不要求客户安装程序，不依赖开发电脑，不购买域名作为处理前提。不把 Worker 改名成 Queue/Workflow/Daemon 后继续引入常驻后台，也不依赖 `after()`/`waitUntil()` 在 HTTP 返回后悄悄完成关键资产发布。

## 2. 推荐的处理结构

```text
浏览器 ──申请上传预留/凭证──→ Next.js（核权、限流、配额）
浏览器 ──原有直传/TUS────→ Supabase 私有隔离桶
浏览器 ──POST complete（小JSON）→ Next.js / Vercel Node Function
                                   ├─核权并原子领取本文件的短期处理权
                                   ├─流式读取、大小/hash/真实格式校验
                                   ├─图片：有界解码、EXIF归一化、生成派生物
                                   └─重新核权并原子提交元数据/配额/事件
浏览器 ←──明确完成或失败───────┘
```

这里仍有服务端计算，但它是**随请求运行并返回结果的函数**，没有需另行启动或租服务器托管的常驻消费者。请求领取权用于跨实例防重，不是等待后台消费的任务队列。

### 处理与状态契约

- 保留同源 API、私有桶、固定路径直传/TUS。文件字节不经过浏览器→Next上传请求，complete仅提交已有预留ID；不能把50MiB附件改为Next表单上传。
- complete每次核验当前Owner/Guest、项目、原上传主体、链接状态与预留；短事务取得处理代次/到期时间后释放锁。下载、解码和Storage写入期间不持有业务锁。
- 服务端重新流式计算SHA-256与字节数，复用已有扩展名/MIME/magic/有限结构规则；不相信浏览器给出的“校验通过”。CAD不执行、不解析几何；ZIP不自动展开为业务文件。
- 图片复用已有Sharp与方向1～8实验：统一方向、sRGB、移除EXIF/GPS，保留标准图尺寸/hash/normalization_version及归一化坐标契约；同时生成所需缩略图。已有标准图和标注引用不重算、不覆盖。
- 使用随机临时目录、限制输入/像素/输出、可终止子进程和全流程期限；`finally`删除临时文件。限额必须在Vercel实际运行环境验证，不能把本机RSS探针称为完整OS隔离。
- 完成时按原锁序重新核验权限，尤其处理期间撤销的分享不能提交；文件资产、派生元数据、配额结算、审计和现有outbox同事务提交，提交后另一端才收到可读事件。
- 处理完成返回200；永久拒绝返回可解释的4xx；临时失败返回可重试错误。并发的另一请求可返回“本文件正在由另一请求处理”的409与重试建议，**不能无消费者却返回已排队202**。
- 请求超时/函数被终止时，短期处理权会到期。状态读取将其呈现为“上次处理未完成，可重试”，不无限转圈；下一次明确重试抢占新代次，旧代次不得迟到提交。
- 未知提交结果先查本预留权威状态；已ready返回同一资产。重试沿用预留和幂等语义，不要求重传已存在原件、不重复计费；已有输出仅在hash匹配时复用，禁止覆盖不可变路径。
- 页面关闭后不承诺自动完成：当前调用可能继续，也可能中断。重新进入先读取权威状态，必要时明确恢复本文件处理。此项是取消持久后台后需接受的体验边界。

## 3. 病毒扫描必须单独决定

**“不要Worker”不等于已批准取消病毒扫描。** 当前所有类型须经ClamAV才ready；不能直接删掉`scan()`并把其余检查叫作“扫描通过”。

| 路径 | 是否需独立常驻Worker | 代价与限制 | 建议 |
|---|---|---|---|
| A. 同步格式校验 + 图片解码/重编码，不做完整病毒库扫描 | 不需要；只用现有Vercel + Supabase | 部署较简单；减少病毒防护层，PDF/CAD/ZIP原件下载仍可能含恶意内容。强制下载/禁止执行不能保证用户在本机打开安全。 | **以简化运行和交互为目标的推荐候选，但安全变化须明确批准后才能实施。** |
| B. 在Vercel请求内按需执行独立扫描程序，之后再处理图片 | 不需常驻守护进程 | 扫描引擎/病毒库打包、Linux二进制、内存、冷启动、更新新鲜度和费用均需独立验证；可能需要平台Beta能力或升级。 | 若必须保留病毒库扫描，可先做不含用户文件的隔离可行性实验；不能保证免费套餐可稳定承载。 |
| C. 经批准的托管扫描服务，再由同步函数完成其余工作 | 不需自租主机 | 新供应商、费用、附件外传及网络往返；非当前技术栈，商业机密可能不能交付外部服务。 | 不作为默认路径，不擅自接入，不发送用户资料。 |

A的保留保障：服务端真实格式/结构核对、大小/hash/配额/限流、私有隔离、有界解码、图片重编码、附件只下载、逐请求授权、历史与事务保护。**这些均不能等价替代反病毒引擎。** 对PDF中的活动内容、CAD阅读器漏洞、ZIP内部未知威胁，不做已检测或已消毒承诺；需要缩减允许格式或增加审查步骤时另列产品变化，不能偷偷禁用已有CAD/ZIP能力。

如最终采用A，新增明确的验证策略版本及`not_performed`扫描状态（字段命名在正式契约中确定），不伪造`clean/scanned`。UI改为“校验文件”“处理图片”“已就绪”，避免暗示杀毒；必要位置说明未进行病毒扫描。原先已扫描资产的历史信息保持原样。

不建议把整个处理器直接搬到Supabase Edge Functions：官方限制包括256MB内存、每请求2秒CPU，且当前环境不支持依赖多线程的Sharp/libvips；`waitUntil()`也受资源期限限制。它不是现有图像/ClamAV处理器的直接替代品。

## 4. 性能、容量与费用边界

- Vercel函数与现有东京Supabase尽量同区；只增加必要的complete调用，不增加图片经浏览器或新第三方服务往返的传输路线。流式hash与校验合并到一次隔离对象读取，派生物一次生成；不为每个派生规格重读原件。
- 同步处理消除的是无人消费/排队等待，**不保证CPU、Storage或数据库更快**。请求会占用函数执行时间，需报告处理阶段和可执行错误，不能将上传100%写成所有处理完成。
- 初始逐文件处理并发建议为1，上传传输仍可有界并行；数据库原子全局/账号配额与并发预算限制跨实例总量，不仅用单个函数进程内计数。与现有并发策略的差异需在测试后定稿。
- 不把整批20文件放在一次函数调用；正常文件可独立完成，单文件失败不拖垮整批。对大图和大附件的请求期限、内存与临时盘设定先实验，不能未经验证承诺沿用所有上限并同时更快。
- 现有效上限仍是策略与供应商上限取小：图片20MiB/40MP、其他附件最多50MiB（当前测试配置）。**此处是待验证的兼容目标，不是新实现已支持**；实验若不能承载，应提供精确失败与替代选择，不悄悄降限。
- 没有固定额外服务器租金；函数CPU/内存、Storage请求/流量仍可能产生平台用量费用，不承诺永久零成本、不自动升级套餐。
- 大文件下载沿用受控权限与撤销约束，单独核对平台响应体/流式/Range行为；不能为规避限制公开桶或悄悄改成长签名。下载方式需要变化时另列差异。

## 5. 清理、历史及当前积压如何迁移

取消常驻进程不能取消孤儿清理责任。建议清理使用**短时、幂等、限批的维护HTTP函数**：在既有Vercel Cron可用额度内按实际需要调度，或由受控管理员显式调用。它只回收过期隔离物/未提交输出，不消费上传任务；属于需要说明的运行配置，不伪装成没有维护工作。Cron频率/鉴权/配额待核对，当前不配置。

清理必须晚于上传凭证失效与处理权到期；确认对象不存在后才释放预留。无访问且无调度时不能承诺自动清理；积压额度要可观测。关闭分享不能自动删除仍有历史引用的文件。

建议按以下次序实施（**本轮不执行**）：

1. 冻结新Worker开发/租机计划，核对现有任务与资产计数；保留当前两份未领取上传，不取消、不伪造ready、不要求先重传。
2. 在独立实验中验证Vercel请求内图像处理、输入限额、时限及选定扫描政策。用户资料不作为初始实验样本；若需Preview部署，另核目标与资源，此次不触发。
3. 从现有Worker抽取可复用的纯校验/转换/结算服务；原扫描策略在新方案正式批准前保持原要求。独立complete路由限定运行配置，避免把所有普通API一起拉长或加载重依赖。
4. 提交最小前向migration提案：为同步执行保留有限处理权/策略记录，精确补充runtime在已核权预留上的所需RLS/列权限；**不使用postgres/service_role替代业务身份，不把Worker全部权限复制给runtime**。数据库方案先审查，未经批准不应用。
5. 切换后旧queued预留由其合法原主体/明确授权恢复流程调用新complete；阻止旧消费者再领取同一任务。保留旧jobs审计记录，标记由新策略接管，而非删除历史。过期/撤销项目明确拒绝，原件与配额通过受控清理处理。
6. 已ready文件、原标准图、标注修订、测量回复与发布成果均不改写。旧缩略图按需、逐文件、有限执行；不在普通列表GET偷偷重建整库。旧派生失败不能阻塞已有文件下载。
7. 独立回归与人工作业通过后，才从部署说明、环境变量和启动入口移除ClamAV/Worker需求；旧角色和表的回收另经审查，不直接drop。服务端SSE/LISTEN仅负责现有事件同步，与上传消费循环分开，不因本次提案自动重建或停用。

## 6. 验证门槛与审查结论

必须新增的隔离验证：

- 原生图片方向1～8、原图坐标不变、真实手机照片及既有40MP边界；恶意/损坏/伪装/超限输入拒绝。测试样本通过不代表所有上传无害。
- 允许的PDF/CAD/ZIP真实样本、较大文件、批量部分失败；选定的扫描政策下记录实际执行了什么。
- HTTP超时、关闭页面、函数中断、处理权过期、新旧代次竞争、客户端重试与未知提交结果恢复；不能多资产、多结算或迟到覆盖。
- Owner A/B隔离、Guest管理拒绝、同项目附件校验、处理期间撤销、未通过校验资产不可见，以及成功后双端真实事件与受控下载。
- 冷/热态、并发、各段耗时、函数内存/临时空间、调用和流量成本；以当前可复现版本对照，未测不宣称更快。大陆真机仍是P0最终门槛。

**审查时需要确定的实质变化**：选择A/B/C中的扫描政策；页面关闭后靠下次访问/明确重试恢复的契约；维护HTTP清理的调度方式；实验显示需改变的文件限额/平台配置。用户“取消Worker”的要求已经明确，不再重复请求该项授权；它不自动批准削减安全保障、升级套餐或生产部署。

本轮交付仅为此文档与范围登记：没有实现/测试新上传链路，没有运行Worker或处理那两份文件，没有发送附件到外部扫描商，也没有修改数据库或任何部署。原上传卡住问题**仍未因出方案而修复**。
