| **FIX-C：真实业务、性能与权限闭环** | 04、05、08、09、10、11 | 在同一当前版本，用少量代表资料合并覆盖注册、双端协作、版本/反馈/归档、真实文件/导出、缓存/事件及普通角色权限。先最小真实复现，出现具体失败才改代码；补改动范围，复用P0/P2已有有效证据 | 真实链路依赖A；与B修复相交的场景使用修复后的版本。OTP发信、浏览器/E2E和真人手机条件提前核实。关闭需注明实际角色/设备/网络和结果；源码变化后只补受影响部分 |

| **FIX-E：真实备份与受控恢复** | 15 | 复用P3-04加密工具及本地证据，在获准新位置补真实数据库＋私有对象恢复；核对hash/引用/固定历史、角色可见性、旧访问失效和新登录，同时落实独立key/异设备副本/留存记录 | 依赖可读源、独立恢复位置和配置/凭据条件；方案准备可提前，不要求等待其他所有条目关闭。只恢复合成资料或明确获准数据，不覆盖原测试库/生产。缺条件时精确记待外部，不能用本地fixture或空备份代验 |

依赖主线是 **A先解除真实链路阻碍 → B修正交互缺口 → C合并验证**；D的资料核对、E的恢复准备可穿插进行。允许独立工具读取/准备并行，不表示自动启动多个Agent或同时修改共享代码。

### 5.1 实施前只做一次轻量分拣

首次分拣建议控制在15～30分钟，优先读本表、当前AGENTS/PRD和各问题最新来源，只追查确有冲突的历史记录，不每包重读全部P0～P3。

1. 确认工作区已有未提交成果及当前运行环境；保护原UI/登录/维护改动，不重置、不覆盖，不把全部混合改动自动提交。证据记录实际源码来源或相关文件指纹，不能只引用旧HEAD/buildId。
2. 将当前包的问题分为**已知缺陷、待验证、配置/运行事项**，为各项确定最小复现、关闭标准和最小必要改动。正常通过的已有功能直接补证，不强制写代码凑产出。
3. 一次列出缺的外部条件：现有合法测试账号、真实手机/移动网络、OTP测试邮箱与发信范围、获准的浏览器/E2E范围、云恢复位置、必要配置/费用决策。先查已有授权/连接配置，缺少才询问，不索要或输出明文密钥。
4. 说明当前包的实现/必要检查估时及外部等待，不承诺未知网络故障的固定解决时间；给出可立即执行和不受阻塞的部分后继续工作。

### 5.2 启动范围与授权沿用

- 本次更新仅是执行规范，**不是五包开工授权**。用户只启动一个任务包时，实施限该包及其必要修复；其他包可以整理已知依赖，不自动开工。
- 若用户明确授权整轮收口，可按依赖连续推进，无需对已授权的例行修改或每个包结束重复请求确认；途中有输入时将其作为当前任务的约束/反馈处理。
- 原有禁止事项与已批准范围继续有效。浏览器/E2E、发信、云端写入/清理/恢复、部署、新资源费用及系统网络变更，核实已有授权后执行；本文件不能代替具体授权。真正需要确认的操作先完成可独立的实现与可审阅方案，再说明具体动作/影响及需要确认的依据。
- 默认一个主Agent维护台账与共享契约。只有获得明确多Agent/委派授权时再拆独立任务；路由、认证、缓存、共享样式和数据库契约先由主Agent协调，避免多个Agent同时重写。完成本包不自动进入P3-05或生产发布。

## 六、保证效率与质量的执行规则

### 6.1 修正范围与设计保留

- 以§一/二关闭标准为准，优先复用当前组件、接口、缓存、核权和维护工具；一次只处理有依据的关联问题。新增非关联问题另记，不无限扩大成重构。
- 界面沿用[定稿](proposals/frontend-unification/README.md)及[三阶段保留边界](proposals/frontend-unification/three-stage-plan.md)：浅色/深色/跟随系统、待办模态/分资料横滑/同框下方详情、七类icon、手机点标注原位双角色弹框、未提交保护和全部既有功能。
- 动效继续使用opacity/小幅transform和减少动态效果规则；不新增重模糊、大阴影或逐帧尺寸/画布动画。新增主要交互、功能删减、改变状态/历史语义或新增服务/收费依赖，不能按“修复”默认为已批准。
- 修复深链接等确需调整API时，明确参数/DTO/404与权限、缓存失效及原客户端兼容；服务端独立核权，不能只靠UI隐藏。保留幂等、修订冲突、固定历史及取消/失权后的生命周期边界。

### 6.2 一批代表资料，合并有效验证

优先复用合法现有账号，在获准隔离环境使用一个最小合成项目：一张照片及七类标注、固定修订的数值/照片/无法测量或补测历史、两版交付、一个私有草稿和版本反馈；另一个Owner用于隔离拒绝。真实文件和设备体验只补少量代表资料。权限/数据只留脱敏标识，凭据和能力地址存ignored安全配置。

同一场景可同时证明多个编号：例如“修改回复→换Tab→另一端发布→取消离开→回来”可覆盖06/08/10；“撤销链接→继续下载/再开本地图片/再次导出”可覆盖10/11。每条证据明确关联哪些编号，避免各包复制同一套流程。历史超过10版的页界可单独用合成元数据补，不强制真实客户造11版。

该样本是可复用准备建议，不是在未授权时创建账户、写云资料、发信或向恢复目标上传业务数据的许可。真实客户文件只在明确获准范围使用。

### 6.3 必要检查集中，验收标准保持

| 变动/事项 | 执行要求 |
|---|---|
| 文档/计划更新 | 核对范围、引用、本地链接和差异；不启动应用/数据库/构建 |
| 已知代码缺陷 | 最小复现→实质修正→相关类型/lint与有意义的边界回归；不为每个可逆排版改动写镜像测试 |
| 待验证事项 | 先验证已有行为。通过则记录；失败先保存现象，再针对原因修复。缺设备/连接则记具体外部条件，不凭想象重写 |
| 权限/历史/事务/传输/恢复 | 做对应定向检查及必要真实普通角色/文件验证；管理查询、mock、本地RLS/fixture的适用范围分别记录 |
| 批次交付 | 合并运行适用lint/typecheck/单测；打包/配置/资源加载受影响时构建。同源码、同环境的有效结果可复用，后续变更只补受影响部分 |
| P3-05最终候选 | 固定候选后的完整自动回归及获准E2E/真实闭环仍归P3-05；此前已完成结果按版本复用，不把同一套验收机械重跑五遍 |

主要精力用于实质实现和关闭缺口；C/E本身以真实验证为核心，已有能力正常时可只补结果，不按新增行数/文件数或“代码占比”制造工作。安全、数据完整性或恢复检查失败不能为了节省验证时间放行。

手感/阅读由少量真实操作集中反馈，Agent能完成的准备与代码先完成，不要求用户为每个按钮填写表格。当前记录的代码完成、历史用户通过与本轮新结果分开保留。

### 6.4 外部阻塞与范围变化

- 同条件下已复现的DNS/TLS/权限拒绝，记录最小脱敏错误及发生阶段后停止重复探测；有新证据/配置变化再验证。不能盲目换TUN/代理/DNS、改共享限流、换管理员身份或关闭TLS来追求通过。
- 一个条目受阻时继续已授权且独立的代码/资料/工具工作。保留阻塞项和所需条件，不把等待、超时或没有反馈视为批准/验收。
- 云恢复工具当前仅支持新本地空库时，不得删除目标门控、临时改连接串或把fixture Auth/Storage结构部署云端。需要真实新目标支持时先准备具体兼容/隔离方案和必要工具，按获准目标执行。
- 已接受的CV精度、PDF栅格取舍、缓存容量/撤销物理边界及取消Worker等继续按§四处理；Agent不能重新纳入强制开发，也不能自行接受新的功能限制。

## 八、进入P3-05的收口条件

1. 15组逐项有处理结论；确定缺陷已修正，所需真实验证已有证据，或非关键限制由用户明确接受。待验证/外部阻塞不自动算完成。
2. 越权、历史破坏、输入静默丢失、错误对象定位及恢复数据不一致等阻断问题不能靠备注放行。新的影响在本台账明确记录并优先处理。
3. 合并已有通过项，明确P0真机/大陆网络/OTP等欠项是否真正关闭；不为清空表格重复实现，也不用旧Preview、本地fixture或模拟设备填真实通过。
4. 向用户交付一份汇总：已关闭、明确接受的限制、仍待外部的条目；由用户明确决定进入P3-05。届时再固定正式候选、对齐锁文件/环境/迁移并集中回归，生产发布仍是另一个授权停点。

本表不声称没有尚未发现的新问题。后续修复以此台账持续更新，代码完成、人工通过和真实环境通过分别记录。
