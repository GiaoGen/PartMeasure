## 1. 结论与设计方向

目前显得简陋的主要原因不是功能少，而是缺少统一的页面骨架、信息层级和操作秩序。新功能逐项加入后，旧布局越来越难承载；不同页面的颜色、圆角、导航、弹层和状态反馈各自发展。推荐一次统一为**清晰、克制的工程资料工作台**：中性底色、白色工作面、蓝色主动作、稳定的两区导航、以照片和工程信息为中心。

交付目标：新用户能理解产品用途，工程师知道当前位置与保存状态，客户知道下一步做什么；首页、登录、项目列表、资料、编辑器、交付、异常页及手机端属于同一个产品。改变布局和操作组织，保留已实现的业务能力、数据语义与权限。

## 2. 对现状的审查

本次依据本地源码、PRD和阶段记录静态审查，没有启动应用、浏览器/E2E、数据库或部署。旧P0截图不能代表当前页面，所以没有据此宣称完成当前界面的实机视觉审查。

| 问题 | 本地证据 | 对使用的影响 | 本次处理 |
|---|---|---|---|
| 三套以上的视觉规则并存 | `globals.css`、`entry.css`、`projects.css`、`workspace.css`分别定义按钮、标题、背景；颜色通过多个局部变量/字面量传递 | 页面之间像不同阶段的原型，组件难以保持一致 | 统一语义设计令牌、基础组件、页面骨架；按页面逐步移除被替代样式，不再叠一层全局覆盖 |
| 大面积带色底板与大圆角抢占层级 | 工作区28px、入口32px圆角；文件夹颜色映射整个页面、卡片、边线与动作色 | 页面显得柔软松散，工程内容不突出，切换文件夹像换产品主题 | 页面与主动作颜色固定；文件夹色保留为圆点/小范围标记，数据不变 |
| 工作区结构不稳定 | 桌面同时摆资料和狭长交付栏；右栏又被标注属性替换；手机单独用两区切换 | 看交付和编辑的上下文不稳定；交付多附件/反馈挤在窄栏 | 桌面和手机均用“资料与补测 / 交付与版本”两区导航；属性检查器固定属于资料编辑视图 |
| 常用动作的可发现性不足 | 项目搜索藏在文件夹标题图标内；新建项目与上传采用浮动入口；项目说明/分享藏在标题展开中 | 首次使用要找入口，操作主次不清 | 项目搜索常驻主工具栏；新建、上传、分享用文字按钮；设置保留在明确的次级菜单 |
| 路由与可见状态不对应 | 工作区section、文件、标注主要只存`useState`；项目进入多为普通`a`；除分享换票外很少与URL联动 | 刷新回到默认视图，返回不容易回到原筛选/原位置，页面切换可能整页重载 | 保留现有业务路径，将允许恢复的视图状态写入查询参数；规范内部导航与返回 |
| 字体与密度缺少语义层级 | 全局16px与局部11/12/13/14/20/21px混用；同类标题/表单在不同容器中被重新覆盖 | 有些地方空，有些地方挤，小字承担了重要信息 | 正文、标签、辅助信息、标题、数值分别定义统一字号/字重/行高 |
| 反馈与弹层缺少统一组织 | 多处原生`confirm`，另有自定义dialog、popover、上下文侧栏；根级loading/error/404均复用入口营销布局 | 操作反馈像系统拼接；工作台出错时突然跳出工作环境 | 统一菜单、对话框、抽屉与内联消息；工作区加载/错误保留所在页面框架 |
| 术语漂移 | PRD为“资料与补测”，现有页面多处为“资料与测量” | 导航和帮助里的同一功能叫法不同 | 对外统一“资料与补测”；工具/表单中按具体含义使用“标注”“测量值”“回复” |

这里的“简陋”主要是组织和一致性问题，不意味着每个已有组件都要重写。已有固定位置预览、属性聚合、角色色、历史默认折叠、图片缓存和草稿保护仍作为基础。

## 3. 后端成熟度简评

**功能完整度已较高，具备小型真实协作产品的后端基础；生产运行成熟度尚未闭合。** 这是有限源码/证据审查，不是新一轮安全审计或运行验收，不给缺少依据的成熟度分数。

- 已有项目/分享/文件/标注/回复补测/不可覆盖交付/反馈/归档/导出等业务域。`db.ts`有受限数据库身份、事务内主体、提交回滚、有界SQL重试与幂等；标注及交付服务检查revision，正式migration包含RLS隔离规则。不是只依赖按钮禁用或前端本地存储的演示。
- 固定修订、回复与补测历史、发布版本、私有文件和导出快照已有实现及定向检查记录，前端可以直接复用这些能力。
- 本机业务数据库连接问题尚未闭合；P2后段不少证据来自本地SQL/合成文件，不能等同真实Supabase Auth/Storage/业务全链路通过。
- 全新注册OTP、真实手机/大陆网络、备份恢复与生产回归仍有欠项，所以不能宣称已经具备可靠正式上线的全部证据。

本次前端重整无需默认重写后端。如设计发现现有DTO不支持某项展示，先用现有真实字段调整方案；不得虚构进度、通知数、最近活动时间、云端自动保存或增加后台流程。确需改接口/权限/认证/数据库时单独列范围，不夹带实施。

## 4. 统一视觉规则

| 项目 | 推荐规则 |
|---|---|
| 页面与工作面 | 页面`#F7F8FA`，主工作面白色；以间距、细分隔线组织内容，不给每层内容套卡片 |
| 主文字/次文字 | `#1F2933` / `#526171`；正文、标签、说明按意义分级，不能靠一律浅灰弱化所有文字 |
| 主动作 | 蓝色`#2459B8`；同一局部任务只突出一个主要动作，如上传、保存、发布或提交 |
| 状态 | 待补充红、待补测黄、已补充绿，均有文字；黄色只作状态色。绿色不意味着尺寸齐全或工程验收 |
| 角色 | 工程师蓝、客户绿，同时标文字身份；角色色与业务状态分开使用 |
| 圆角 | 输入/按钮6px，文件缩略图/小工作面8px，对话框12px；页面大区不再用28–32px圆角包裹 |
| 间距 | 4/8/12/16/24/32/48；标题和内容、区块和区块使用固定关系 |
| 字体 | 中文优先使用设备系统黑体：`Segoe UI Variable / Segoe UI / PingFang SC / Microsoft YaHei UI / Microsoft YaHei / Noto Sans CJK SC / sans-serif`；标题正文同一字体体系，工程数值使用等宽数字 |
| 字号 | 页面标题约25px，区块20px，正文/桌面控件14px，常规输入16px，标签/辅助13px；12px仅极次要元信息。首页主标题约39px，手机约31px；不把工作台做成大字号宣传页 |
| 字重/行高 | 正文400、标签/小标题500、主标题600；中文正文约1.55–1.65，标题约1.25–1.35 |
| 图标与动效 | 统一20px线性图标与笔画；七类标注工具继续仅icon，复用现有图形，不展开为文字工具栏。悬停/键盘聚焦可看工具名，具备可访问名称、选中态和触摸目标；新建/上传/分享等业务入口可保留文字。状态转换约120–180ms；尊重减少动态效果，不做整页波纹换色/装饰入场 |

字体策略优先不增加字体下载、依赖或外部CDN；Windows与手机允许系统字体形态不同，但保持字号、字重、数字对齐与布局一致。以后如需跨平台完全一致，再评估自托管中文字体体积。排版参考typography-system方法；该技能引用的配对CSV及design-tokens生成工具在当前安装中未提供，本方案不声称已生成/验证完整字体系统。正式实施用仓库内单一语义令牌源，不额外引入工具链；密集界面14px是光学密度调整，较大标题沿16×1.25比例取整。

## 5. 页面与视图定型

### 5.1 首页与认证

- 首页采用简明的产品介绍：一句用途、工程师入口、三个实际步骤、一张同风格工程资料示意。展示真实已有的标注/补测/版本能力，不用不存在的AI卖点、假统计、装饰性功能卡片或巨大空洞Hero。
- 登录独立聚焦表单，减少现有左右两块相似文案；顶部统一品牌和返回首页，注册/验证码仍是已有认证步骤的不同表单状态。
- 登录时只提示登录相关要求；12位密码要求与OTP说明主要放注册状态，不每次登录重复解释注册流程。注册失败、验证码错误、网络故障分清，保持既有接口和限流行为。
- 不新增密码找回、社交登录等后端未支持功能。保留密码管理器和验证码自动填充；提供显示/隐藏密码等纯前端能力。

### 5.2 项目列表

- 稳定的窄侧栏：品牌、全部项目、私有文件夹、底部账号入口；文件夹颜色仅作标记。
- 主区标题“我的项目”，右侧明确“新建项目”。下方常驻项目搜索、进行中/归档/全部筛选及当前结果数，复用现有服务端查询/分页。
- 项目默认采用整齐的行式列表：项目名称、说明、所属文件夹、创建日期、归档状态和次级操作。窄屏简化次要列，点击项目进入工作区。
- 不显示后端尚未提供的项目完成率、未读数、最后操作人或“最近编辑”时间；没有说明时弱化缺省文案，不让每一行都是“暂无项目说明”。
- 分开真正空列表、筛选无结果和加载失败。新建表单继续在对话框完成，保留名称/说明/文件夹已有语义。

### 5.3 工程师项目框架

- 顶部稳定显示“我的项目 / 项目名称”，右侧“分享项目”“项目设置”；标题不再同时承担唯一的设置/分享入口。
- 顶部下方所有尺寸统一两区导航：**资料与补测 / 交付与版本**。归档状态显示明确只读横条，可查看/下载，Owner恢复/撤销沿用已有能力。
- 不常驻第三个业务区，不新增项目总览/独立聊天/复杂看板。待办仍属于资料与补测，**保留现有左下角铃铛入口、计数/异常提示与浮窗**；可补充文字入口，但不能替换铃铛或增加打开步骤。打开后沿用现有资料分组、横向卡片与下方固定位置详情，具体约束见§5.7。
- 工作区内部切换时尽量保持已经准备的内容和草稿；未提交交付草稿/回复不能因换Tab、刷新通知或隐藏视图被静默清空。

### 5.4 资料、标注与属性

- 资料浏览态占用整个工作面。顶部“上传资料”为主按钮；类型/排序、导出为次级动作，PDF/ZIP保留现有选择和上限，不另造导出中心。
- 图片用统一缩略图比例和文件名行；CAD/PDF等文件以整齐文件块显示名称/格式/大小/来源。保留既有上传/拍照入口与队列；可以补充显式上传按钮，但不能删除手机浮动上传快捷入口。**图库缩略图上的标注保留可点热区；点标注与点图片空白处分开处理**，不能统一改成打开编辑器。
- 桌面编辑态：左侧约200px的文件定位栏、中间最大化画布、右侧约320–336px属性检查器。受限宽度先收起文件栏。**手机点击图库标注仍打开现有原位信息弹框，不强制先开大图/编辑器或进入另一页。**
- 文件栏只用已有已加载资料和分页，保留当前定位，不为装饰全量预读。
- 顶部显示“返回资料 / 当前文件名”、未保存/保存中/已保存/冲突状态、明确“保存修改”。画布操作与文件级操作分组，七类工具、撤销重做、缩放、CV入口均保留；**线段/圆/点/文字/角度/圆弧/椭圆使用现有icon，不改为常驻文字按钮**。
- 属性区按现有业务聚合为：编号/名称与类型 → 人工工程字段 → 测量要求/备注 → 当前客户补充/补测 → 默认折叠历史。保留数字编号、黄色“待补测”及双方身份颜色。
- 右侧始终表示当前标注/文件属性，不再同时承载交付列表；属性里不重复嵌入整张照片。历史固定位置按需查看，待办定位仍可使用必需的预览。
- 明确手动保存，不借此次改版加入自动保存、自动确认或自动补全真实尺寸。CV仍可关闭/撤销/失败手动回退。

### 5.5 交付与版本

- 作为独立的第二个Tab使用主工作宽度，结束目前多附件、反馈和发布表单挤在狭长右栏的情况。
- 主体显示明确的最新版本身份、发布时间、版本说明、附件列表、下载/ZIP；相关客户反馈与收到/接受记录按版本聚合，使用现有语义。
- Owner私有草稿以清楚的独立编辑区域呈现，保存草稿与发布区分；发布不可覆盖、最多附件等规则不改。Guest只看发布内容，保留追加更正、收到/接受及撤销自己本次访问记录的已有能力。
- 历史仍默认折叠、每页10版，展开某版原位看详情；不为新布局自动读取全部版本/全部反馈。

### 5.6 客户手机端

- 继续同一个项目协作页，顶部仅项目身份、角色/权限说明、必要项目说明；不出现“我的项目”、工程师设置或标注工具。
- 两区导航与桌面叫法一致。资料区有待补项时优先呈现“需要你补充”；空项目直接显式上传；已有资料但没有待补时正常浏览/继续上传。
- 先看固定测量位置和工程师要求，再用现有三条方式提交：填数值、拍照上传、无法测量。默认不强迫理解所有工程字段；测量帮助原位展开。
- 当前补齐框只突出一个主提交动作；成功后明确“已补充”，能够看到提交内容，不写成“工程师已确认”。
- **保留用户截图中的手机原位弹框路径**：资料图库 → 直接点击照片内的标注/编号 → 当前页弹出该标注的信息框。Guest显示已有测量字段/单位与提交、可展开照片/说明/其他回复方式；Owner显示已有标注属性、工程字段/测量要求、客户补充、补测与历史。两者继续按角色核权，不给Guest工程师编辑能力。
- 弹框背后保留图库与滚动位置，关闭后回原位置；不在弹框里重复塞一张大照片，不强制先跳转全高任务页或编辑器。保留原有关闭、切换/离开时的未提交输入保护。只在必要范围统一字体、间距、边线与焦点；键盘出现时用已有可见视口适配/内部滚动保证输入与提交可达，不能以适配名义取消弹框。
- 上传/拍照入口有文字，不只剩图标；底部安全区与软键盘可见区域留空间，提交按钮不得遮挡输入。需要时滚动到当前输入，避免强行固定多个底栏。

### 5.7 待处理事项：保留弹框与已认可的排版

附件二对应现有`IssueInbox`/`TaskCardRows`。第一版文字虽写了复用，但没有画出完整浮窗，且主稿的摘要条容易让人误以为要替换它；本版补齐，不对这一块重新组织布局。

- **桌面和手机均为弹框**：从提醒入口打开，有遮罩、关闭与焦点管理；背景工作区与滚动定位保留。不改成独立路由、常驻列表、底部展开区或抽屉。设计稿单独画出弹框内容是为了审阅内部排版，不表示将其嵌入页面。
- 保留“待处理事项”标题、关闭按钮、黄/红/绿状态图例，以及加载/失败/重试/空态/分页状态。
- 每份资料一组：文件名一行、左右浏览按钮、下方横滑小圆角卡片。卡片只保留编号/名称；黄待补测→红待补充→绿已补充的分组顺序与现状一致。手机仅卡片行横滑，整个页面不横溢出。
- 点卡片仍在**同一个待办浮窗列表下方**打开/切换固定标注预览和填写区；列表不消失，不跳照片编辑器。再次点选/收起的行为保留。
- 同标注同修订多个字段继续聚合，历史默认折叠、角色色与测量方式保留；跨资料切换、未提交保护、失败重试和有界批量准备沿用已有实现。
- 本阶段只允许与全站协调的字体、边线、间距和焦点细节，不改变卡片结构、大小密度、横滑方式或增加新的筛选步骤。进一步调整须先另行呈现并获批准。

## 6. 路由、返回与状态规则

保留现有五类业务页面，不新增后台页面或更换认证/Guest会话协议。现有分享地址仍有效，换票后继续清除原始令牌；不把令牌、邮箱、回复正文或未保存草稿放进URL。

| 路径/状态 | 约定 |
|---|---|
| `/` | 产品入口；工程师进入登录/项目，客户使用已有分享链接 |
| `/login` | 已有登录/注册/验证码状态；可从受限的站内目标恢复导航，禁止任意外链跳转。认证成功的真实会话核验与清理边界维持原实现 |
| `/projects?status=active&folder=…&q=…` | 列表文件夹/状态/已提交搜索可恢复；参数名为方案示例，最终与现有schema对齐。连续输入不逐字符写历史 |
| `/projects/[id]?section=files` | 默认资料与补测；显式Tab切换进入浏览器历史 |
| `/projects/[id]?section=deliveries` | 直接恢复交付区 |
| `…?section=files&file=…&annotation=…` | 已保存资料/标注的定位；服务器仍逐项核权。无效、已隐藏或不可读目标显示就地提示，回退可见列表，不暴露其他项目详情 |
| `/s/[token]` → `/s/session?project=…` | 保留原换票路径；session页附加允许的section/file/annotation视图参数，绝不重复写入原令牌 |

- 普通内部导航使用框架Link/客户端导航；私有动态页面不大范围自动预取，必要时`prefetch={false}`或只在明确意图后读取。下载链接仍走现有受控文件读取，认证/退出/换票保留必要的整页导航和缓存清理。
- 回到项目列表时恢复原状态/文件夹/搜索和合适滚动位置；不拿带任意外部URL的returnTo直接跳转。文件列表恢复仅在同账号/同项目且核权仍有效时生效。
- Tab/明确文件导航用push，连续搜索修正/缩放/鼠标选取等高频变化用replace或内存；不把每次选择/拖动都堆进浏览器返回栈。
- dirty状态由现有编辑器/交付/回复统一汇报。站内离开使用统一“继续编辑 / 放弃并离开”确认；浏览器关闭/刷新继续使用原生beforeunload。浏览器前进后退不能只靠beforeunload：实施时专门处理popstate、待定目的地和未保存视图恢复，不清空输入后才询问。
- URL恢复后等当前DTO读取和权限通过才打开具体对象；不重新提交写请求，不恢复已撤销权限。旧的无参数链接、`theme`外观参数保持可进入；外观参数不再改变整页主色。
- 页面有稳定标题，导航完成将焦点送到合理标题/主区；关闭弹层还给触发者。加载/失败/404在相应页面骨架内显示，不一律套首页宣传面板；Guest故障不引导客户去Owner项目列表，也不泄露链接失效细节。

## 7. 全站交互组件与状态

只建设本产品确实复用的轻量基础：Button、IconButton、Field、Select、StatusLabel、Tabs、Menu、Dialog/Drawer、InlineNotice、EmptyState、LoadingSkeleton。统一高度、焦点、禁用、忙碌和危险动作规则；不默认引入整套新组件库。

| 情况 | 统一表现 |
|---|---|
| 空项目 | 解释先上传或分享给客户，并提供已有可执行入口 |
| 筛选无结果 | 显示筛选条件与清除入口，不误导用户重新建项目 |
| 局部读取失败 | 在原位置重试，保留已加载其他内容与草稿 |
| 保存/提交中 | 就地显示明确状态、防重提交；不能只用一个全页spinner |
| 保存冲突 | 保留本地修改，清楚解释远端已变，沿用原有重载/放弃规则，不静默覆盖 |
| 上传/导出失败或取消 | 保留已有上限、取消和整包重试契约，显示失败原因和真实可做动作 |
| 归档 | 可看/下载/导出；编辑上传发布不可用，Owner恢复入口明确 |
| 失权/分享失效 | 结束受控读取并清理相关权限作用域内容；显示已有允许范围内的说明 |
| 隐藏文件/撤销分享/发布 | 确认内容包含对象与结果，危险动作与普通保存分开 |

## 8. 实施边界与顺序

**允许范围（方案获准后）**：`src/app`页面结构/路由呈现、`src/components`布局与前端状态、CSS/令牌/图标、必要的导航和样式契约测试；保留所有未提交登录修复。不改变`src/lib/server`业务规则、API契约、RLS/Storage/正式migration、网络、部署或服务采购。

按用户最新要求，整个P3-01分三个子阶段，分别交付、分别检查与交接，不一次性改完整站。原A–D交付单元由下表替代；详细包括/不包括项与交接标准见[三阶段任务边界](three-stage-plan.md)。用户后续已启动A，代码与必要检查交付见[A记录](../../P3-01A-entry-ui-2026-10-25.md)，人工体验待验；B于2026-10-26获明确启动并已交付代码及必要检查，见[B记录](../../P3-01B-workspace-ui-2026-10-26.md)；C于2026-10-26获明确授权，现已交付代码与必要检查，见[C及合并交接](../../P3-01C-delivery-ui-2026-10-26.md)；不自动进入P3后续阶段。

## 9. 验收口径

- 能一眼看出首页、登录、项目列表、工作台和客户页属于同一个产品；字体/按钮/边线/圆角及交互反馈不再各页不同。
- 相比现状有清晰结构变化：全站统一框架、稳定两区Tab、明确上传/分享、宽交付区、桌面固定属性检查器；手机图库快捷弹框与已认可的待办排版保留。
- 所有七类工具、历史、原位补测、私有草稿、反馈/接受、归档、三项导出及取消能力保留；权限/状态含义不变。
- 七类工具保持icon；待办按资料横滑且详情在同浮窗下方；Owner/Guest均能在手机图库直接点击标注打开对应原位弹框。图片空白点击路径、关闭后的图库定位、未提交保护、原有快捷入口同样必须保留。
- 文件夹/筛选/Tab/文件定位按允许范围可恢复；刷新、站内返回、浏览器返回与前进不意外丢失未保存输入；退出/换账号/失权不恢复私有数据。
- 覆盖约360–430px手机、768px窄屏、1280–1440px桌面；无整页横向滚动，文字缩放200%时主操作仍可用；照片画布内部缩放/平移单独处理。
- 键盘焦点可见、菜单/对话框可关闭且还焦；重要信息不只靠颜色；手机主要触摸目标至少44px，表单输入不被软键盘/底栏遮挡。
- 必要检查合并执行相关lint、typecheck、导航/状态保护相关单测及最终build。不为纯样式新增逐像素镜像测试；本阶段不自行浏览器/E2E、部署或解决已有网络问题。
- 最后由用户少量试用桌面编辑、手机回复、Tab/返回、导出选择和阅读手感。无真实运行证据的设计稿不得标成体验通过。

## 10. 审阅时需要确定的主要方向

推荐整体批准以下方向后实施，避免每个小按钮反复审批：

1. 全站统一中性白灰/蓝色主动作；文件夹色缩为标记，结束整页换肤。
2. 两区Tab统一桌面/手机；交付退出右侧窄栏，独占第二个Tab的工作宽度。
3. 桌面资料编辑使用画布+固定属性检查器；手机保留图库直接点标注的Guest补齐/Owner属性弹框，保留既有属性聚合、角色色和折叠历史。
4. 新建/上传/分享等业务动作补充明确文字入口，保留待办铃铛和手机上传等已有快捷路径；统一URL/返回/未保存提醒。七类标注工具是明确保留的icon例外。
5. 待处理事项沿用现有布局，不用摘要条/新任务页替换；任何功能删减另列并先获明确批准。

设计约束自检：无渐变；黄色仅业务状态、不是品牌主色；无霓虹、玻璃、光球、空洞Hero或假功能卡片；外框/分栏/弹层均有实际任务目的，不新增无意义多层容器。维持两大Section、Guest极简和人工尺寸边界。
