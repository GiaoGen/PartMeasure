## 改了什么

| 改动 | 对使用的影响 |
| --- | --- |
| 已知照片标注时，合并读取标注文档、同标注各测量字段、最近回复与补测原因 | 首次点击不再先查列表、再逐条请求完整详情；合并后的HTTP仍只进行一次正常Auth和限流预检、一份业务事务 |
| 新增明确的 `IssueCurrent` 当前视图，单独缓存；原完整详情及 `/history` 契约保留 | 当前表单只携带最新回复/审核和历史总数，不把截短数据冒充完整历史 |
| 历史展开后才请求，默认每页20条；保留证据、角色配色及固定位置 | 平常操作不等待全部历史，展开后可继续读取更早记录 |
| 可见照片图层每批最多6张，返回预算2MiB；各文件继续经过RLS和可见性检查 | 图库同时出现多张照片时，减少重复核权和事务往返。后台批次有界；点击的排队照片可提前读取，单个失败文件不拖累整批 |
| 待办同卡片多字段共享当前详情批次；标注补充区由聚合结果统一驱动子表单 | 减少每个字段各自查一份完整详情。多个刷新来源碰到同一在途读取时合并，不先取消再重发 |
| 当前视图、完整历史、图层与聚合数据沿用统一缓存/修订失效 | 服务端写回不能倒退revision；关联证据变化精准失效，普通无关上传不清掉当前详情；换账号后迟到聚合结果不能重新播种旧数据 |
| 修复SSE再验证时将Auth临时网络故障当登录失效的问题；补充脱敏失败分类 | 临时依赖故障走重连，实际无权限仍关闭访问；保留现有SSE、游标补偿和退避 |
| 补建旧图片缩略图 | 原隔离项目18张全部补齐320/640版本；列表GET不做转换，无常驻Worker |

没有增加持久身份缓存、放宽私有桶或RLS；不改变客户提交即绿色、补测为黄色的流程，也不改标准图、归一化坐标和历史。没有新增依赖、schema迁移或付费资源。

## 必要检查结果

固定隔离资料的少量对比，使用真实受限runtime角色及相同资料。下表只统计业务DAL，**不含HTTP Auth/限流预检、图片传输、浏览器渲染**；是单个小样本，不是p95或全站提升承诺。

| 读取链路 | 改前 | 改后 |
| --- | --- | --- |
| 标注 → 相关任务 → 完整详情 | 3份业务事务，21次SQL往返，5.48秒 | 1份业务事务，7次SQL往返，2.42秒 |
| 当前任务单独/同卡片批读 | 每条完整详情独立事务和历史读取 | 每批最多6条，共用1份事务；该样本单项1.53秒 |
| 图库可见图层 | 每张单独事务 | 每批最多6张共用1份事务、6次SQL往返；固定资料批次约1.73秒 |
| 完整历史 | 详情初始化时已取回 | 展开后按页读取；另用已有4条真实历史、内部每页1条连续读取4页，核对无丢失/重复；公开接口固定20条/页 |

这份首次读取样本节省约56%的业务等待；空历史样本的JSON体积没有显著减少，提速主要来自减少跨境SQL往返，不能归结为Supabase服务器执行SQL本身需要几秒。

另做一次图库与当前任务同时读取：两连接已建立时pool合计等待约0.3ms，总耗时约1.45秒。此有界样本没有显示应扩池的证据，因此本次保留**max=2、idle=10秒**，未进行无依据的扩池或反复调参；不声称覆盖全部部署并发。

隔离数据检查包括：跨项目/其他owner拒绝、Guest可见标注过滤、无效Guest拒绝、批次上限、旧完整详情与当前最新回复的一致性、真实历史与分页游标边界。HTTP路由单测另确认聚合读取经过正常Auth和限流、非法批次也记账、旧 `/history` 没有被改成分页/截短契约。

缩略图：执行前缺18张，执行后缺0张，新增36个衍生对象、103,268字节；18张标准图hash前后一致。任务单次最多24张，先预留配额、再处理，按内容hash创建不可覆盖对象并事务结算；重跑跳过已存在版本。使用既有受限维护角色，不重启已退休Worker，不改扫描标记。

代码检查：28个相关文件定向lint、`npm run typecheck`通过；9个相关单测文件、60项通过，涵盖缓存、批次取消/优先级、身份隔离、路由兼容、回复及属性。历史缓存另按当前任务revision隔离，避免当前状态先更新时复用旧首屏历史。没有启动浏览器/E2E、全量云端业务回归、build或部署；集中收尾检查按方案留到第三阶段。

证据：[读取对比](evidence/performance-stage2/reads.json)、[真实分页及并发](evidence/performance-stage2/history.json)、[缩略图补建](evidence/performance-stage2/thumbnails-applied.json)。源码入口为 `src/lib/server/interaction-reads.ts`、`src/components/interaction-reads.ts`；可重复执行的受限补建脚本是 `scripts/performance/backfill-thumbnails.ts`，默认只预览，显式 `--apply` 才写入。

## 用户可直接试的三个动作

使用包含当前代码的**本地开发版 `npm run dev`**；旧 `npm start` 构建及旧Vercel测试站的应用代码不会自动更新。本次只更改原隔离Supabase的数据衍生缩略图，没有发布应用。

1. 从资料中第一次点照片标注，再在编辑器切换两个标注，感受属性/补测原因是否更早出现。
2. 在待办选择同标注有多个测量字段的卡片；展开历史，确认旧值、补测原因、附件与“更早的记录”正常，未提交输入仍保留。
3. 打开有多张旧照片的资料，确认缩略图出现；图层仍在读时点击其中一张，检查当前操作是否能优先响应。

只需反馈仍慢或出错的具体位置，不需要自行统计性能。真实大陆手机网络、注册数字OTP及P0整体外部验收仍按原约束单列，本次未宣称通过。
