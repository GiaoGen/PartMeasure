## 本轮交付

- `npm run ops:status`：默认只报告环境是否配置，不探测网络；显式`--database`才用原隔离维护角色读取积压计数，不用无主体RLS零行冒充正常。没有新增公共管理接口。
- `npm run ops:backup -- keygen/create/inspect`：密钥独立、备份默认私有，AES-256-GCM逐文件加密；数据库导出快照、全部私有对象引用/hash、正式migration来源组成同一备份集，最终manifest提交前任何错误都不放行。
- `npm run ops:backup -- restore --apply`：仅全新、本地、命名与注释均受控的空库和全新文件目录；先验证所有内容，再单事务恢复、核对全部业务表指纹、使旧分享/Guest失效，最后发布私有文件及迁移来源和verified标记。不会覆盖原测试库、创建云项目或把fixture系统schema部署云端。
- `npm run ops:cleanup`：将P3-03的默认dry-run一次性维护工具接入明确运行入口，没有配置自动Cron或执行云删除。
- `.env.example`只增加注释形式的维护配置名；备份和key在ignored私有位置，额外忽略backup目录/加密文件/key扩展。README与旧P0-4运行文档移除当前启动路径中的ClamAV/Worker要求，历史部署证据仍保留并明确旧版本范围。

没有新增依赖/lockfile版本、常驻进程、收费资源、migration或前端页面。定稿UI、浅深色、待办弹框、手机标注弹框和低成本动效保留，没有为运维添加用户操作步骤。

## 备份与恢复的具体边界

1. **数据与文件一起覆盖**：pm完整schema/数据/RLS/ACL/触发器/序列，auth必要记录及可用迁移历史；file_assets（包括软隐藏/旧版关联）和image_derivatives的所有固定私有对象，逐个核对字节数/hash。数据库备份不能替代文件备份。
2. **明确未覆盖项**：不稳定quarantine/TUS传输字节、外部SMTP/Provider/域名/环境密钥、DB角色密码和应用源码不伪装进“完整托管备份”；活动Auth能力表数据排除。中断上传恢复为需新上传，原记录/额度不被静默抹掉。配置/凭据与候选源码由独立清单/密码库恢复。
3. **私有且可鉴别**：新目录Unix0700/文件0600；Windows对新维护目录限制继承ACL，当前用户/SYSTEM/管理员可访问，不改整个工作区。逻辑名称参与GCM认证，替换文件名/混合不同集合/错误密钥/损坏/大小/hash变化均拒绝；不打印内容或凭据。
4. **有界**：最多20,000对象、1GiB数据库dump、100MiB单对象、8GiB整集、16MiB manifest、20分钟工作deadline；流式逐项处理，PG连接/语句及子进程可取消。超限失败，不能截断后称备份成功。
5. **不复活访问**：恢复快照先逐表内容核对，再使全部分享撤销、Guest会话到期。校验旧历史仍存在，但不会因为恢复旧备份重新开放旧链接。云端Auth服务/JWT配置迁移与重新登录必须另有真实证据。
6. **目标与留存**：试运行计划RPO≤24小时、变更前加备份；RTO工程目标≤4小时（当前≤5GiB账户规模，非实测结论/供应商承诺）。建议保留7份每日＋4份每周，至少一个异设备加密副本且密钥独立。没有实际调度/外部副本时，不宣称已满足RPO。

完整说明及命令入口见手册，备份、维护和恢复都不能作为P3-05生产发布授权。
