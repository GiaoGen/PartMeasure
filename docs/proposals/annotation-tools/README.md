# 照片标注工具调整提案

2026-10-20。状态：**方案已获用户批准并进入实现**。用户明确“开始基于现有的代码实现这几个功能”，随后澄清椭圆默认用于斜拍正圆的直径 Ø，可选长半轴 a；本文件已按澄清更新。实现与检查见 [实施记录](../../extended-annotations.md)。独立示例仅供看外观，不代表真实 UI 验收。

## 当前到底有什么

核对 `package.json`、锁文件、`src/`、`experiments/`、`scripts/` 后：没有 OpenCV 依赖或识别管线，没有 Canny/Hough/轮廓拟合入口。当前 `annotation-canvas.tsx` 只提供手动线、圆、点、文字；`annotations.ts` 的几何类型也只有这四类。当前圆必须满足标准图片像素空间的等半径校验，不能当作椭圆使用。

OpenCV 候选/吸附、角度/圆弧原列在 PRD P1，缺失记录见 `docs/P0-4/06-p0-gaps.md`。不是入口隐藏或用户操作错误。本轮继续采用纯手动工具，不加载 OpenCV，不增加照片上传/打开的计算或网络依赖。后续若实现，推荐单独的“辅助选取”：用户明确触发、只处理当前选区、候选经人工接受才成为标注；加载失败仍可手动。不展示可点击但无功能的识别按钮。

## 推荐显示与操作

| 工具 | 工程师画法 | 画面表达 | 默认待补字段 |
|---|---|---|---|
| 线段 | 两点确定端点；保留现有拖动/端点编辑 | 两端垂直短端标、线内小箭头（指向端点），文字放中部；不画通向零件轮廓的长引出线 | 长度 |
| 圆/孔位（已有） | 沿用画圆与半径控制点 | 保留圆轮廓；直径用 `Ø`，半径用 `R`，两者不能混写 | 当前选择的直径/半径，孔深仍可单独要求 |
| 角度（新增） | 按“顶点 → 第一条边上的点 → 第二条边上的点”三步；轻量步骤提示、预览、Esc 取消 | 两条定位射线和夹角弧；默认较小夹角，可切换“反角”；选中后可拖顶点/两臂及显示弧半径 | 角度，单位固定 `°` |
| 圆弧（新增） | 依次点“起点 → 弧上的中间点 → 终点”，自动生成**经过这三点的示意圆弧** | 只画选中的弧段；可选半径指示线及 `R`；三点决定经过哪一侧，不猜最短弧 | 默认半径；工程师可改为弧长或圆心角，也可明确添加多个独立字段 |
| 椭圆（新增） | 拖动起止点确定第一完整轴，松开后调垂直轴；允许垂直轴更长，支持中心移动与旋转 | 椭圆轮廓；选中时显示轴线、控制点；默认显示人工孔径 `Ø` | 默认圆孔直径；可选长半轴 `a`；允许仅作定位 |

画完进入现有「标注与属性」，不再出现发布提醒步骤。工程师可直接填写已知值；所要求字段留空并保存后自动待补。客户点标注直接填写、传照片或说明无法测量，提交后待确认；工程师在原位确认/退回。圆弧多字段独立审核；椭圆只要求当前选择的孔径或长半轴，不生成双轴待补。选择“仅说明”则不生成待补。

角度的三点预览、圆弧的拟合、椭圆旋转只用于定位和绘制。**照片中的夹角、像素半径、椭圆轴比都不能当作零件真实测量值自动填入。** 斜拍的圆孔在照片上可能是椭圆，画出椭圆也不能自动得到真实孔径；此类默认补测人工孔径 Ø；可选长半轴 a，但不会从椭圆图形自动换算孔径。圆弧的实测半径、弧长、圆心角也不自动互算，避免把不同来源拼成未经确认的结果。

## 线段细节：对应用户参考图

- 端标与线段垂直，不固定为屏幕竖线；斜线也随方向正确显示。
- 默认 12 px 短端标、2 px 线宽、6 px 左右小箭头；缩放时按屏幕尺寸保持可读，不改变几何端点。选中加深颜色，只有工程师看到编辑控制点。
- 长度显示 `120 mm`；直径才显示 `Ø50 mm`，不能因为参考图有 Ø 就给普通线段都加 Ø。
- 尺寸文字默认居中、近水平阅读，在笔画后加浅色实底/描边增强照片上的对比；短线空间不足时文字移到线外，箭头转向外侧。显示层偏移不移动被测位置。
- 中央文字、端标和尺寸线都是同一标注的命中目标；可见短端标与隐藏触摸命中区分开，手机目标建议至少 40–44 px。
- 不画参考截图中从两端向下延伸的长尺寸界线；保留的仅是端点附近短端标。示例中的灰色零件轮廓仅作背景参考。

## 如何保持工具栏简单

桌面建议常驻“选取、线段、圆/孔、角度”，把“圆弧、椭圆、点位、文字”放进“更多”；手机沿用一行工具栏和“更多”，不增加第三个主 Section。客户看不到绘制工具。画完自动回到选取，保留单会话撤销/重做。多点工具用明确的“还差哪一点”提示，Esc/取消结束临时图形，不提前保存半成品。

名称、人工值、单位优先显示；操作说明/测法和高级几何字段保持可选。三种回复方式直接可见。图片旋转是视图操作；椭圆旋转手柄改变该标注的位置方向，二者不能混淆。

## 已批准的契约扩展

1. 线段端标先作为纯渲染改动，统一修改 Konva、大图只读、缩略图 SVG、历史快照呈现；只改一个画布会造成两端显示不一致。
2. 新增 `angle / arc / ellipse` 几何类型并版本化，旧四类数据和固定历史快照保持可读。仍基于 EXIF 标准图的原图归一化坐标；不把屏幕像素、DPR、端标大小存成几何。
3. 角度保存顶点和两臂端点，以及较小角/反角的显示选择、显示弧位置；这是图形几何，不是人工确认的真实角度。
4. 圆弧保存有顺序的三点，起点/经过点/终点的身份固定；服务端拒绝重合或近共线样本，校验拟合后整段弧在图内。需要整圆时使用现有圆工具。拟合在标准图像素空间计算后回到归一化表示。
5. 椭圆推荐保存中心与两条轴的端点（均归一化）；两轴垂直关系、旋转与边界在标准图像素空间校验。不能直接在不等宽高的 `[0,1]` 空间判垂直/半径，也不能解除圆的等半径约束来冒充椭圆。旋转后的完整轮廓也须在图内。
6. 测量字段由现有 `dimension / holeDepth` 扩展为明确的 quantity，如 `dimension / holeDepth / arcLength / angleValue / majorRadius`；对应长度/角度单位和校验分别处理。不能只给现有长度下拉框加 `deg`：回复、审核、确认回填、待补去重、数据库约束、单位换算和历史都需要识别字段。长度不允许换算为角度。
7. 照片原位协作仍复用独立 issue/response/review，一个要求字段一个待补项；几何/测量含义变更结束旧未完成项并保留快照，按新位置重建。仅调整标签位置、端标样式等显示设置不重新催客户测量。

## 推荐实施顺序及边界

① 线段样式统一 → ② 角度手动闭环 → ③ 三点圆弧 → ④ 可旋转椭圆与默认孔径补测 → ⑤ 后续独立评估 OpenCV。每一步检查保存恢复、跨角色、快照历史和单位校验，不一次塞进完整 CAD 工具集。纯显示调整不新增网络请求；新手动工具沿用本地 Konva/SVG，不新增计算服务或常驻进程。

本提案的推荐默认是：端标+小箭头；角度不显示照片计算的数值；圆弧默认补半径；椭圆默认孔径 Ø、可选长半轴 a；OpenCV 后置。用户已批准实施以上范围，详情及尚待人工检查项见实施记录。

## 独立示例与验证边界

- `annotation-tools.svg / annotation-tools.png`：四种显示静态示意，里面的尺寸均为虚构的人工示例值。
- `preview.html`：离线交互样例，可切换图形、填写/清空人工值；不调用接口、不保存、不使用账号/照片/令牌，也不是正式编辑器。
- `generate.mjs`：用现有 Sharp 生成示例 SVG/PNG/HTML；无新增依赖，运行 `node docs/proposals/annotation-tools/generate.mjs` 可复现。
- 最初方案轮次只核对代码和渲染独立示意；后续用户已授权正式实现及必要隔离迁移，仍不启动浏览器/E2E、不部署生产。PNG 的视觉核对不代表新增工具的真实绘制、拖拽、保存或手机触摸已通过。
- 后续实现验证：非正方图片、EXIF 标准化、缩放/DPR/窗口变化、旋转椭圆、大小弧/反角、短线标签、非法退化几何、长度与角度单位、椭圆默认直径/可选长半轴、跨角色只读及旧快照。手机手势与可读性单列人工试用。
