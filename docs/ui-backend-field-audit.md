## 核对结论

本轮三个改动——删除上传说明、调整撤销/重做位置、点击标注打开手机弹窗——**均不要求新增数据库字段**。现有数据足以保存弹窗中的工程属性、测量要求和回复。剩余事项须区分「缺字段」「接口没返回现有字段」「仅前端状态」，避免为弹窗或工具按钮新增无用列。

| 需求 | 仓库中已有数据或契约 | 结论 |
| --- | --- | --- |
| 线段、圆/孔位、点位、文字的位置 | `pm.annotations.geometry`，归一化坐标；图片标准宽高、hash、normalization_version | 已有；弹窗/缩略图复用同一基准 |
| 名称、人工尺寸、单位、直径/半径、孔深、孔型、螺纹、备注 | `annotations.metadata` JSON；`metadataSchema` 中 `name/dimension/unit/circleMeasure/holeDepth/holeType/thread/notes/source` | 已有；不需要每个输入再建一列 |
| 保存、修订、隐藏及历史 | `annotations.revision/deleted_at` 和 `annotation_revisions` | 已有；撤销/重做为当前编辑会话状态，不等于删除服务端历史 |

## 接口待补：优先于新增字段

建议 Owner/Guest 的文件提醒列表摘要返回 `annotationRef: { id, revision } | null`，并支持按 `annotationId` 过滤，分页游标绑定项目、文件和标注条件。关联仍必须由后端核权并读取既有外键；不能相信客户端提交的 project/owner 归属。普通文件说明返回 null。

当前前端在用户需要对应提醒时，读取一页文件提醒，再通过已有详情接口比对真实 `fileId` 和 `target.annotationRef.id`；最多并发 4 个，不按名称猜测。结果保持服务端顺序，读取失败不混入未核对的提醒；切换标注后过期结果不展示。有后续分页时提供继续查找，不把一页结果冒充全量。工程师未展开相关提醒时不启动这组详情读取。

客户在完整当前列表中只有一个明确可操作的对应提醒时，可直接进入回复表单；多个提醒时保留选择。关闭弹窗后，迟到的读取结果不会再次自动弹开。历史测量使用发送时的固定修订，仍可展开查看原测量位置，不把当前移动过的标注冒充旧目标。

这套前端兼容方式能复用现有接口，但多提醒时有额外请求和详情历史载荷。后端补充摘要及过滤后应移除这些逐项关联读取。**该接口修改本轮未实施。**

## 先前仍待后端实现的事项

1. **用户文件夹持久化**：文件夹实体的 owner、名称、说明、七色标识、时间，以及项目的可空 `folder_id`；按分类分页与 Owner 隔离。当前仍为页面内存，不能承诺刷新或跨设备保存。完整草案见 [项目分类后端待办](projects-ui-backend-followup.md)。
2. **私有标注草稿与显式发布**：当前保存按现有权限可读。若要求「草稿客户不可见，发送才公开」，须设计草稿/发布修订、可见性、发布状态和权限，而不只是前端添加开关。尚未实施。
3. **多标注/多提醒一次原子发送**：需服务端批次事务、批次幂等、逐项修订校验和失败恢复；现有单条保存与创建接口顺序执行。批次实体/字段需与业务契约一起设计，尚未实施。
4. **永久标注编号**：当前编号为可见列表序号。若需跨隐藏、跨设备和历史恒定，须分配文件内不可复用编号并随提醒快照保存；现有 annotation ID 已稳定，UI 序号不是永久标识。尚未实施。
5. **批量预览和小缩略规格**：优先补充带权限的批量读取、修订摘要、派生规格与失效规则；并非弹窗输入缺字段。若新增派生资产元数据，再独立审查。
6. **完整项目搜索**：名称、说明本已存在；需要分类/关键词查询、索引评估与对应游标契约。当前已加载项目的前端搜索不能等价于全库搜索。

第 2–5 项详细边界另见 [照片标注与测量提醒记录](workspace-measurement-ui.md)。这些是待设计/待实现事项，不能因本轮前端完成而标为后端完成，也未因此提前实施 P1/P2。
