## 结论与建议

成熟开源算法值得复用，但本批证据不支持直接全面替换当前算法，也不支持宣布 CV 已提高操作效率。EdgeDrawing 在安装板示例上减少了包围整块板的错误大椭圆，能找到部分小孔边缘；同时会输出装饰卷边、旋钮等非孔轮廓，且在本轮尺寸阈值与参数下六张管件图没有保留圆／椭圆候选。Canny/轮廓拟合也存在安装板大椭圆、管件侧面反光和背景误候选。

建议保留手画后局部贴合，把圆／椭圆候选维持为主动触发、少量展示、人工选用。10月25日已由 Codex 补全全部候选审查与参考轮廓对照；按用户调整的定位，建议有限接入已有 OpenCV.js，不以用户填写试验表为本阶段关闭前提。EdgeDrawing 的浏览器编译、包体与取消代价仍未验证；本轮没有做自定义 WASM 编译、建立新服务或接入 AI。

## 已完成的范围

- 已收集36张不同文件的真实照片，6类各6张；搜集约17分钟，候选总数36，未继续搜图。照片来自MPDD，原作者Jezek等；固定镜像修订、来源、许可、文件哈希与尺寸见[来源清单](evidence/p1-03/sources.json)。
- 两种算法均完成36张批处理，无最终批次异常；27个分析者预置粗画探针覆盖六类和线段／角度／圆／椭圆。含空白背景、纹理背景、小孔、斜拍管口、反光、多边缘、非孔圆形等情况。
- 独立算法保持手画局部范围，角度以第二点作顶点；无匹配／含糊时保留原草稿。按需输出最多12个圆／椭圆候选；没有全图线段候选或自动物理尺寸。输入与输出复用现有几何校验。
- 生成两种算法的全部候选叠图、全部探针对照、两张总览和图册。原照片及改图只留本机忽略目录，没有进入正式网站或Git。
- 独立人工页提供纯手动、局部贴合、候选、组合四种方式，四类几何、拖点修正、撤销、取消／关闭辅助、候选选用、轮廓与孔的分开评价及JSON导出。UI沿用现有白底、冷灰、蓝色、小圆角和控件尺寸；属于独立实验，没有改正式编辑器布局或交互。

## 技术观察

以下是输出数量和是否调整，**不是精确率、召回率或正确贴合率**。

| 照片类别（各6张） | Canny/Hough 圆／椭圆 | EdgeDrawing 圆／椭圆 |
|---|---:|---:|
| 黑色支架 | 1 / 3 | 8 / 1 |
| 装饰支架 | 0 / 3 | 24 / 24 |
| 白色支架 | 1 / 0 | 2 / 2 |
| 连接件 | 0 / 6 | 12 / 5 |
| 安装板 | 3 / 7 | 5 / 2 |
| 管件 | 0 / 5 | 0 / 0 |
| 总计（去重、预算过滤、单图限12个后） | **5 / 24** | **51 / 34** |

| 27个粗画探针 | Canny/Hough 调整／保留 | EdgeDrawing 调整／保留 |
|---|---:|---:|
| 线段（8个） | 5 / 3 | 6 / 2 |
| 角度（5个） | 1 / 4 | 1 / 4 |
| 圆（5个） | 1 / 4 | 3 / 2 |
| 椭圆（9个） | 1 / 8 | 1 / 8 |
| 合计 | **8 / 19** | **11 / 16** |

“保留”同时可能是合理回退或漏贴合，必须由人工区分；“调整”也可能贴错边。预置探针按照片视觉放置，不是工程师实际操作，也没有独立人工真值。少量正向示例不能外推为泛化通过。

本次单轮本机运行观察：

| 项目 | 实测 | 解释边界 |
|---|---:|---|
| OpenCV.js Node初始化 | 237.6ms | 已有本地文件，非浏览器网络首载 |
| Canny/Hough计算中位数／P95 | 22.94 / 56.23ms | 36图，每图全图候选，指定6图另含探针；不含图像解码 |
| EdgeDrawing原生初始化 | 164.3ms | Python原生库导入，非WASM |
| EdgeDrawing原生计算中位数／P95 | 19.50 / 71.12ms | 单线程，全图边缘＋线段＋圆／椭圆，含结果整理；不含解码和TS意图匹配 |
| OpenCV.js文件 | 10,872,779字节 | 未压缩发行物，非实际网络传输量 |
| 原生cv2二进制 | 85,000,704字节 | 仅本机对照工具，不是浏览器将加载的包体 |

两种运行时、算法与搜索范围不同，不能据上述毫秒数宣布一种更快。原生算法先全图提取内部特征，再用同一意图匹配器约束位置、范围和方向；JS路径重算局部ROI。详细配置、版本、哈希、逐图输出与探针见[技术证据](evidence/p1-03/technical-results.json)。

## 可选操作体验（不再是本阶段必做验收）

本机入口：[只读结论与实例](http://127.0.0.1:3103/)；[可选操作页](http://127.0.0.1:3103/manual.html)；[两种算法图册](http://127.0.0.1:3103/gallery.html)。用户已将评估交给 Codex，无需执行下面的原人工试验流程。服务关闭后，在 `D:\PartMeasure\experiments\cv` 执行 `npm run serve`。详细复现步骤见[实验README](../experiments/cv/README.md)。

快速首轮约10–15分钟：

1. 先看原图确定目标和相同任务编号。可从 `metal_plate-01` 的一条板边、一个角、中心孔，以及 `tubes-03` 的斜拍管口开始，分别覆盖四类几何；对含糊轮廓可明确记录“无法判断”。
2. 同一目标各做一次纯手动和局部贴合；交替先后顺序。点击开始会加载照片并计时，画好后立即点“目标已标好（停止计时）”，再填写评价和保存记录。`completedMs` 才是任务时间，`wallMs`另含评价时间。
3. 在有孔、装饰支架、旋钮和管件图主动触发候选。分别评价轮廓是否正确、是否为孔；漏候选不清楚时留空，不能填0代表未知。选用、拖动修正、撤销和关闭辅助会记录。
4. 导出JSON。页面记录只在内存，刷新前必须导出。首轮用于发现明显问题；判断精确率／召回率还需先独立确定目标范围与真值，不能仅审核已输出候选后宣称召回率。

EdgeDrawing模式使用原生预计算结果；其检测等待不计入网页任务时间，不能与JS实时模式直接比较效率。切后台、空任务、失败、中断、未停止任务计时等记录均须单列。这里只能核对几何，不能从像素推断真实孔径或真实角度。

手机体验尚未测，本机服务仅绑定loopback，不能用桌面窗口缩小代替真机，也没有为此对外开放端口或部署站点。真实工作照片、实心台阶轴和更广背景仍缺；按用户要求不再自行扩选，后续需要时由用户提供工作场景照片。
