# 客户提交即完成 · 2026-10-21

用户本轮明确要求：取消工程师确认、仅要求补测时标黄、客户提交后标绿、照片编辑区域显示编号。本记录替代 PRD/旧阶段文档中必须「submitted → 工程师确认」的交互要求，其余私有访问、修订、历史和权限约束继续适用。

## 当前行为

- 初次缺少必填测量信息：红色。客户提交数值、照片或无法测量说明后：绿色，标为「已补充」，不再加入工程师待确认队列。
- 工程师在客户回复下展开「要求补测」，填写原因后：黄色；客户再次提交后恢复绿色。原回复、附件和补测理由均保留。
- 客户仅有回复权限；不能修改几何、工程字段或要求补测。工程师需要人工录入/修正时，继续使用原「标注与属性」工程字段编辑及修订历史。
- 编辑器显示当前照片列表顺序的编号，与属性列表一致；随缩放维持可读大小。缩略图及单个问题快照不额外显示编号。这是当前图片内的定位序号，不是跨删除操作保持不变的永久业务编号。
- 待办只统计初次待补/要求补测；已补充及旧确认记录可在历史查看。

## 数据及接口

保留既有 `submitted` 数据状态，但语义改为「已补充」，不伪造自动确认或工程师审核记录。原 `confirmed`/确认值保留作历史；新确认写请求由服务状态机拒绝，工程师的新增动作仅有补测。

不需要 migration，也没有修改云端 schema、数据、RLS 或部署。回复、附件、状态、审计及幂等结果继续在原事务一次提交；补测依旧核对 issue 修订与最新 response ID，Guest 在服务端被拒绝。

标注读取接口在现有授权查询中关联本项目、本标注、未关闭问题的最新数值回复，返回 `collaboration.values[field] = {value, unit}`；核对固定快照的几何含义、当前要求字段及圆的 R/Ø 语义。显示优先采用工程师已填写值，否则采用客户原回复及其原单位。客户回复不写进 Owner-only annotation metadata；照片/无法测量回复不生成虚构尺寸。工程师调整目标后，旧问题按原规则关闭，新目标重新待补。名称修改不清空已收到的数值。

`collaboration.pending` 只计初次待补，新增 `remeasure` 独立计数。提交和补测均失效本项目标注/问题/文件缓存，复用既有事件同步；不新增轮询、转发层、服务或依赖。
