# 工程师工作台与客户协作页 UI 设计提案

最新一轮照片编辑和测量提醒的实施、后端缺口与验证边界见 [照片标注与测量提醒 UI 实施记录](workspace-measurement-ui.md)。其命名与上下文侧栏布局替代本文件上一轮对应描述。

2026-10-18（Asia/Taipei）。状态：用户已确认手机资料单列、主页图标在顶栏最右侧，并明确授权实施；本轮前端已实现，实际视觉与手机交互待人工检查。禁止修改后端、禁止自行打开浏览器验证的约束继续有效。

## 页面与现有边界

用户所称 `/projects/[slug]` 对应仓库现有 `/projects/[projectId]`；本轮不改路由参数、项目 ID 或认证流程。客户页沿用 `/s/session?project=`，现有分享令牌换取受限项目会话的流程保持。

当前两页共用 `Workspace`。工程师可管理/标注/审核/发布；客户仅查看授权项目、上传资料、回复、下载已发布成果。布局趋同不改变权限，不能把工程师的私有交付草稿显示给客户。

## 本轮拟定布局

- 顶栏：左侧保留 PartMeasure（手机可缩减品牌占位）；项目名称以整条导航栏为基准居中，箭头紧邻名称；小房子图标独立放在顶栏最右侧，点击到 `/projects`。点开项目名称在下方展开说明：先以小号文字说明「工程师工作台」或「客户资料协作」，再显示「项目说明」与正文。默认收起，避免重复占据主区。未登录客户点击主页会按现有 `/projects` 认证流程进入登录；不因此获得工程师项目列表。
- 桌面：下方只保留两个主要区域，同时可见。左侧约 3/4 为「资料与补测」，右侧约 1/4 为「交付与版本」。窄桌面须给交付区保留可用最小宽度；具体断点实施时按排版确定。
- 资料主区：以缩略图片和文件格子为主体，不再用图片名称列表占据主要位置。图片显示实际授权图片；非图片保留格式、名称、大小等必要信息，CAD 不解析几何。点开图片才进入大图与既有标注/补测上下文。
- 将原上传区域的资料选择、进度、失败重试与处理状态收拢至资料区右下角「上传」，保留在该区域内部，不能漂浮到交付区。手机从按钮展开「拍照」「文件」「相册」。桌面选择文件并支持现有允许格式；上传后的素材按等待/上传/处理/就绪/失败状态进入资料区，不提前宣称扫描完成。
- 手机：同一页面顶部用「资料与补测 / 交付与版本」切换，默认资料区；资料中的图片和文件均保持单列，不采用双列网格；不把桌面的 3:1 双栏缩成手机窄双栏。上传按钮只在资料区显示。
- 待办补充建议（待审查）：资料区标题旁保留简短的待审核/待回复数量入口，避免客户有补测任务时无法发现；本轮以资料排版为主，不展开完整补测详情。
- 风格沿用 `/projects`：低饱和度实色、较大圆角、简短过渡、弹层退出仅渐隐；遮罩沿用已批准的暗色半透明例外，不使用渐变或毛玻璃。减少动态效果偏好下缩短运动，不宣称未经实测的性能。

## 上传入口的限制

三个选项最终均复用现有资料上传管线与私有权限。拍照通过浏览器允许的相机/文件选择能力提供，不能保证所有手机浏览器会按 capture 提示强制打开后摄；不支持时提供文件/相册选择。不能静默打开相机。

资料区上传固定为 material 用途。成果附件依旧从「交付与版本」的工程师入口进入 delivery 用途，不因整合上传按钮而混淆原始资料和正式成果。上传状态、批量进度、防重复、重试与刷新恢复必须保留，入口改动不能变成新上传后端。

## 暂未定稿、后续必须补齐的清单

1. 项目名称/说明编辑、分享链接生成/复制/撤销/重建的具体入口和确认层级。
2. 文件加载更多、文件类型/大小限制、扫描中/失败/重试、跨设备刷新、空项目上传引导。
3. 图片大图、缩放/平移、方向基准、工程师几何标注与字段、保存/修订冲突/未保存离开保护；客户仅只读标注。
4. 文件级问题、待办、测量方式、数值/照片/无法测量回复、补测证据与历史；工程师确认/重测及来源记录。默认已有任务的客户仍需能发现任务。
5. 授权下载、文件删除和历史引用保护，不能用公开图片 URL 绕过私有文件接口。
6. 交付区窄栏内的摘要与详细编辑层级：私有草稿、成果上传、多附件清单、说明、原子发布、幂等/并发、已发布不可覆盖；客户仅看已发布集合并逐文件受控下载。
7. 现有错误、加载、会话失效、链接撤销、重试与权限拒绝状态；桌面同时挂载两个区域时不能让一边刷新抹掉另一边未保存草稿。
8. 手机安全区、键盘、触控、较长项目名/文件名、不同浏览器与真实网络实测。

本轮不提前开放完整历史管理 UI、交付反馈/接受、导出等尚未授权功能；「交付与版本」先展示现有最新已发布成果与工程师现有草稿能力。

## 后端待办判断

顶栏说明折叠、双栏布局、移动端选择来源及上传 UI 入口本身不需要新增数据库字段，优先复用现有接口。图片缩略展示先核对现有受控图片接口的能力、尺寸与处理状态；如确需增加缩略规格或批量读取能力，另记接口/派生文件策略提案，批准前不改后端、不开放公开 Storage。

文件夹配色跨设备继承依赖上一页文件夹持久化草案，当前并未接入数据库；工作台先采用基准低饱和度配色，不伪装已取得持久分类颜色。

## 实施记录

- 两页共用的 `src/components/workspace.tsx` 已调整：顶栏品牌、整栏居中的项目名称和箭头、最右侧主页；名称下展开角色说明、项目说明，工程师继续从折叠项访问现有说明编辑与分享操作。主页导航保留未保存修改确认。
- 桌面两区域同时挂载，约 3:1，并为交付区保留 220px 最小宽度。手机小于等于 700px 时切换区域，资料网格单列；隐藏区域保留挂载状态，上传、草稿不因切换组件而被清空。
- 资料编辑与交付编辑的 dirty 状态分别记录，汇总用于离开/刷新保护，防止一个区域的状态更新清除另一个区域的未保存标记。
- 主区展示真实受控图片预览和普通文件格子。图片走原有 `.../files/:id/preview`，懒加载、异步解码并支持失败占位；使用 `next/image` 的 `unoptimized` 以保留浏览器对私有接口的认证请求，不进入不转发认证头的优化代理。没有新增公开 URL、Storage 策略或图片服务。当前使用已有标准图，尚无更小缩略派生规格，不宣称已完成大批量原尺寸图片的性能验证。
- 选择图片/文件后，在资料区内展示既有标注编辑、文件级问题、详情与下载/隐藏操作；返回资料列表入口保留。补测汇总改为可展开的轻量入口，保留优先排序、计数、刷新、历史和回复/审核详情。客户不再自动跳进首个任务详情，而是在资料区上方看到明确的待回复入口。
- 资料 `UploadQueue` 增加前端 floating 形态：桌面上传按钮唤起文件选择；手机展开拍照/文件/相册。右下角按钮按资料区边界定位，手机交付区显示时隐藏；上传进度、失败重试和处理状态仍在资料区内显示。已就绪文件从队列转为资料展示，避免完成项重复占据队列。成果和回复证据上传保留原入口/用途，不混入资料上传按钮。
- 交付区继续复用现有 `DeliverySection`：仅工程师可操作私有草稿与发布，客户仅查看已发布成果及受控下载；未添加完整历史管理、反馈或接受流程。
- `workspace.css` 只作用于当前工作台；较大圆角、低饱和度实色和短过渡沿用项目列表页；说明/上传浮层退场仅渐隐，尊重减少动态效果偏好。未引入依赖或动画框架。
