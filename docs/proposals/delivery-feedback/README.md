# P2-02 客户反馈与接收方案

2026-10-25。预计3–5小时有效工作，含实现及必要定向检查，不含审批和人工试用等待。状态：用户已明确回复「批准，按此接入现有页面」。

## 位置与操作

沿用原交付区、冷灰蓝样式、文件行及历史折叠方式，在所查看版本的附件下增加轻量反馈区；历史版本也在该版本原位显示。不新增页面、弹窗或工作区。

```text
最新版本 V003 / 展开的历史版本 V002
版本说明、附件、下载（沿用）

客户反馈与接收
有效记录：已收到 1 · 接受 0
客户 张先生 · 已收到 · 时间
  附带说明……
▸ 更早记录

客户称呼（可选）             仅客户端
留言／说明……
提交留言    已收到    接受本版
本次记录：已收到             撤销本次记录
```

工程师只读查看客户反馈和接收历史，不代客户标记，也不删除客户记录。客户按钮在对应版本下原位提交，始终注明版本号；已发布版本可操作，草稿没有反馈入口。姓名可选，只作来源说明，不是认证身份。双方查看时都保留「客户」文字身份，沿用客户绿色和原有排版；不新增卡片层级。

## 提交、撤销与更正

- 留言正文必填；「已收到／接受」可附说明。提交失败保留输入，可重试；重复请求复用幂等键。
- 留言只追加，不直接覆盖或删除；填错时追加一条更正说明。
- 同一版本、本次客户访问只保留一个当前接收标记，可从未记录直接标为已收到或接受，也可由已收到升级为接受。重复标记不会增加有效记录；接受不再降为已收到。
- 可撤销本次访问的当前标记：追加撤销记录，原文／时间保留，当前状态回到未记录。升级后撤销不会自动恢复更早标记。
- 不同客户访问的记录独立，不允许凭相同称呼撤销别人的记录。旧访问记录继续可读，但不以自填称呼恢复修改权限。页面提示「可撤销本次访问提交的接收记录」。统计按有效访问记录计算，不宣称是认证人数。
- 接受只表达对指定交付版本的接收意愿，不证明工程质量合格，不改变补测／测量状态，也不锁定后续版本发布。

## 状态、输入和手机

默认展示最近记录，更早记录按需分页，每次20条；版本附件不重复读取。列表空态、加载、失败和重试原位展示；后台更新和反馈提交不卸载表单、不覆盖已输入文字，也不关闭Owner正在展开的上传／草稿编辑区。切换历史或收起有未提交内容的反馈区时，保留已填内容或明确提醒后再离开，不静默丢弃。

手机保持原区域单列，按钮换行，触摸目标至少40px；输入有明确标签，结果及失败可被辅助工具读出。未输入正文时禁用提交留言；请求期间禁用重复写入；已收到／接受状态对应禁用重复动作。原位记录关联版本，避免客户误认为在回复最新版。

## 数据与实施边界

新增本阶段正式migration，仅原隔离项目`rvysclscetfqicpnzlra`：版本反馈追加表、必要复合外键／索引、默认拒绝RLS、当前客户会话归属与不可更新／删除保护。复用认证、事务、幂等、现有delivery事件和缓存失效，不增加依赖或服务。

每请求验证分享有效性、项目和已发布版本；Guest可追加自己的记录，Owner只读。数据库不向浏览器开放直写；日志不记称呼、正文或令牌。单版记录量和写入频率有界；不修改已发布附件或测量记录。

范围仅P2-02；保留此前SLDPRT／SLDASM文件头限制移除的修正，不借此重构上传／版本发布流程或实施P2-03～05。无浏览器／E2E或部署，做必要类型／lint／相关单测及少量真实隔离事务与权限验证；阅读、操作和手机手感最后交人工。
