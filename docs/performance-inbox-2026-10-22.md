# 待处理事项浮窗定向优化

2026-10-22。依据用户「那开始进行针对优化」，实施已说明的同图详情预读、点击优先及画布复用。沿用既有非生产 Preview 授权，保留现有业务流程与布局。

## 原因

「读取测量位置与当前补充状态…」等待的是当前待办 JSON：固定标注快照、照片元数据、最新回复/补测原因等。不是重新计算坐标，也不是图片下载进度。此前每个未缓存标注点击后才请求；即使同图字节已缓存，整个详情与画布仍被一起重建，并且画布必须等 JSON 后才挂载。

## 本次实现

| 位置 | 改动 | 预期体验 |
| --- | --- | --- |
| 打开待办浮窗 | 延迟120毫秒准备首个资料的少量当前详情 | 第一批卡片在点击前有机会准备好 |
| 选择卡片 | 只预读同资料中当前、后一项、前一项及再后一项，最多6个待办字段 | 同图相邻标注减少点击后等待；不遍历整个项目 |
| 请求调度 | 点击与预读共用规范缓存键、共享请求；排队的点击可越过另一批在途读取 | 不重复请求正在预读的同一待办；点击不被无关预读串行挡住 |
| 同图切换 | 画布按资料/图片版本保留，填写表单按标注修订重建 | 已显示图片保持，减少拆除、解码和重新出现的过程 |
| 新目标尚未返回 | 保留照片并清空旧标注，拿到新待办的固定快照才绘制 | 不把上一项的位置错误展示成当前项 |
| 已有详情 | 继续复用既有30秒新鲜/2分钟有界保留与后台更新 | 返回看过的标注可先展示；提交仍由服务端检查权限和修订 |

预读只取当前详情，不取完整历史、不下载相邻照片。浮窗关闭/切换/卸载取消对应预读消费者，不中断仍被点击读取使用的共享请求。浏览器报告省流量或2G时跳过预读。权限、账号清理、事件失效及缓存总量沿用现有实现；没有新增数据库表、迁移或服务资源。

## 手感验收

打开待办后，依次切换同一张照片的几个标注，再返回看过的标注；观察图片是否保留、位置是否正确、填写区等待是否减少。再确认未保存填写的切换提示、提交后状态、补测原因及历史仍正常。

首次打开、预读尚未完成、快速切到预读范围外、缓存被淘汰或事件失效时仍可能等待真实接口。此次减少重复工作与点击时等待，不承诺首次网络请求零延迟，也没有将自动测试当作体验通过。
