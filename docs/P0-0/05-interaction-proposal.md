# 首轮双端交互设计提案 v0.1

日期2026-10-16。**待项目所有者明确批准，未实施正式业务UI。** 下列线框是文档内低保真；代码首页仅是工程标记，不能视为批准后的产品首页。本提案覆盖P0核心路径；P1教程、P2版本管理/导出仅留扩展位置，不提前实现。

## 用户、前提与目标

工程师：已登录且拥有项目，目标是把资料变成明确补测项、审核后交付；桌面优先。客户：持有效分享链接，免注册；目标是上传现有资料，按指定位置填值/拍照或说明无法测量；手机优先。客户不学习几何工具，不审核自己，不发布版本。可选显示名只是标签，不是身份认证。持链即可读取客户可见资料的边界须在工程师生成链接时明确提示。

项目工作台永久只有两个顶层Section：**资料与补测、交付与版本**。文件详情、画布、待办是Section内选择状态；不增聊天、看板、文件夹树或“AI助手”Section。登录/项目列表是进入工作台的页面，不伪装成更多工作区。

## 主方案：工程师桌面三列，同页处理目标与请求

```text
PartMeasure / 项目列表 / 安装板             [分享链接] [项目说明]
项目名称 · 当前保存状态
资料与补测（选中） | 交付与版本
─────────────────────────────────────────────────────────────
资料列 240px       图片/文件主视图（弹性，优先空间）    请求列 320px
[上传资料]         [选择][线][圆][点][文字]            待审核 2 / 待客户 3
全部 / 图片 / 附件 [缩放 - 100% +][适应]              #孔A 内径
文件名/类型/来源   ┌ 图片及正式标注                ┐  测量位置+方法
photo1.jpg         │                              │  客户回复/证据
part.step          │                              │  [确认][要求重测]
说明.pdf           └                              ┘  历史（按时间展开）
逐行列表           非图片显示名称/大小/下载+文件级问题 [新建请求]
─────────────────────────────────────────────────────────────
```

外层用grid分列与两条分隔线；画布边界是操作视口而非装饰卡片。工具有文字标签/tooltip、快捷键；只读时移除编辑工具。选中文件→图片选几何→填工程字段（可无尺寸）→保存正式标注→创建请求（名称、目标、测法和说明）→预览客户可见结果→发送分享链接。新建/编辑请求在右列替换选中详情，保留画布上下文；不叠多个modal。文件级问题直接在右列填写，不出现空Canvas。

新建项目：列表页主动作“新建项目”，输入名称/可选说明；创建后到空工作台，“上传资料”与“分享给客户先上传”为两个清楚动作。分享抽屉显示有效期、持链权限、复制和撤销/重新生成；撤销是明确二次确认，提示旧链接失效及短签名/已下载副本边界。没有照片时只显示上传/项目说明，不显示可发几何任务的按钮。

备选：文件列表→全屏图片编辑，问题详情用抽屉。优点小屏画布更大，缺点桌面频繁切换/遮挡目标；推荐主方案桌面三列，在宽度不足1100px时转为该备选，不缩成三列窄条。900px以下工程师只做资料/审核优先；专业编辑可进入专门全宽状态但仍属于资料与补测，复杂精细编辑提示建议桌面，不让客户核心流程受此限制。最终阈值通过真实内容测试微调。

## 路径A：空项目先让客户上传

```text
手机 · 客户协作（空项目）
┌──────────────────────────┐
│ 安装板 · 资料协作         │
│ 资料与补测 | 交付与版本   │
├──────────────────────────┤
│ 请先上传零件正反面照片    │ ← 工程师项目说明，不伪装测量任务
│ [拍照/选择照片]           │ ← 首屏主动作
│ [选择CAD/PDF等文件]       │
│ 格式与单文件限制说明      │
│                          │
│ 上传队列：文件名 进度 取消│
│ 失败项 [重试]；成功项保留 │
└──────────────────────────┘
```

工程师新建→复制链接→客户打开→直接看到上传→选择多张照片/附件→逐个进度→“已上传，工程师可查看”，不强制注册或填写姓名。分享页在页面加载时bootstrap换会话并清理地址token，无需多余入场步骤；无效/撤销时展示“链接已不可用，请向工程师索取新链接”。默认不显示其他项目或站点营销Hero。

打开文件选择器的拍照支持取决于手机浏览器；提供相册/文件替代，不只依赖getUserMedia。HEIC拒绝明确提示“请转为JPG或将相机设为兼容格式”，不能上传后无声失败。附件行用名称、格式、大小、来源和时间，不为STEP放假预览。

## 路径B：工程师已有照片与测量任务

```text
手机 · 客户协作（有待测项）
┌──────────────────────────┐
│ 安装板                   │
│ 资料与补测 | 交付与版本   │
│ 待回复 3项   [补充上传]   │ ← 待办优先，上传仍可见
├──────────────────────────┤
│ 孔A：请提供内径      1/3 │
│ [照片+高亮只读孔位]       │ ← 先解释“测哪里”
│ 使用卡尺内测量爪          │
│ 工程师说明 [怎么测?]      │ ← P1教程另提案，此轮只显示方法/说明
│ [填数值] [拍照上传]       │
│ [无法测量]                │ ← 明确三条等价可选路径
│ 选数值: [   ] [mm ▼]      │
│ 可添加证据照片            │
│ [提交回复]                │
│ 提交后：待工程师审核      │
└──────────────────────────┘
```

工程师上传→标注孔→指定内测量爪→创建请求→发链接。客户首屏看到待办摘要与第一个任务的具体位置，打开目标图片可放大/平移，不能拖标注。数值可带照片；只拍照无需数值；无法测量必须有简短说明。输入过程中暂存在该设备内存，切离前提示未提交；敏感草稿不默认长期写localStorage。重复点击同幂等键，显示“提交中”；断网保留当前输入并可重试；成功后状态“待审核”并能看本次证据。

客户提交→Owner在同一右列看原图定位、数值与证据→确认或填重测原因。仅照片时Owner选择“根据照片人工录入”，最终值/单位+来源备注一起留历史；无法测量不强迫伪造数字，Owner可要求其他视角/另建请求。要求重测后旧回复折叠保留，客户待办重新出现并解释原因。confirmed后需新请求纠错，默认不提供静默改值。

## 交付与版本Section

```text
资料与补测 | 交付与版本（选中）
成果集合 v1 · 发布日期 · 说明       [下载全部（P2）]
文件名         格式       大小      [下载]
文件名         格式       大小      [下载]
历史版本（P2阶段开放完整列表）
Owner：[添加成果附件] [发布]；Guest只见已发布集合
```

P0-4仅简单多文件成果集合与下载，发布前显示文件清单/说明确认一次，底层保留version。P2再开放历史列表/反馈/收到或接受；接收语义不等于技术质量验收。成果文件用表格行/移动列表，不套多个阴影卡片。未发布时客户显示“尚无交付，工程师发布后可下载”，不展示假样例。Owner的补测完成不自动触发发布。

## 关键状态与可执行反馈

| 状态 | 工程师 | 客户 |
|---|---|---|
| 空项目/非图片 | 上传或发链接；附件可提文件级问题 | 首屏上传；没有假测量项 |
| 加载/图片损坏 | 内容区域进度/重试，不锁整页 | 保持任务文字，图片重试，能报无法测量 |
| 上传失败/断网/部分成功 | 每文件失败原因、单项重试、成功项不重复 | 保留队列，切网络续传；若凭证过期重新授权 |
| 格式/大小/项目配额超限 | 具体上限、删除/扩容由Owner处理 | 不反复重试；提示联系工程师或转换格式 |
| EXIF标准化/扫描中 | “文件处理中”，未ready不可标注 | 可继续其他上传，不误报资料已可用 |
| 提交中/未知结果/重复 | 保存状态、同幂等键查询/重试 | 保留输入；成功后一次记录，不出现多个结果 |
| 并发编辑409 | 显示他处更新，重新载入/复制当前未存字段 | 新状态提示，保留当前内容供对照 |
| 撤销/过期/权限不足 | 生成新链接需明确操作 | 清除私有内容；索取新链接，无登录强迫 |
| 无法测量/仅照片 | 看来源，人工判断，不显示假确认数值 | 两条路径都可提交，不强制读卡尺 |
| 删除有历史引用 | 显示保护原因/引用，不直接删除 | 历史仍可看，不给删除别人文件功能 |
| 未发布/下载失效 | 发布核对/重签名、重试 | 无成果空态；失效时重新申请，不暴露路径 |
| 归档 | 只读提示，恢复Owner操作P2 | 提案只读，禁新回复/上传；待批准 |

状态文字贴近动作，用aria-live反馈异步结果；成功不只靠颜色/短暂toast，失败字段内说明。危险动作（撤销/发布/逻辑隐藏）显示具体对象与后果；常规上传/回复不反复弹确认。请求取消不假定服务端已回滚，先查询真实结果。

## 桌面、手机与可访问性

桌面用文件列、画布、请求列并置；客户端桌面保持“任务+目标图/回复”两列，仍无编辑工具。手机单列：目标图→方法→三种回复方式，底部提交按钮不能遮输入框/安全区；Section导航只有两项，不增加底部五tab。工程师手机将文件列表与单文件详情互斥显示，以返回按钮保留位置；桌面快捷键只在画布聚焦时生效，输入框内不拦截删除/撤销。

所有动作可键盘Tab/Enter，明显focus、表单label、错误aria-describedby，Canvas外有对应文字请求与对象列表，不能只靠颜色/图形传意。触摸目标≥44×44 CSSpx，支持浏览器放大，双指仅在图片视口内缩放且可退出，页面正常滚动。普通正文16px，桌面元信息最小14px；数值与单位并列，单位有可访问名称。颜色与状态文字冗余编码。

## 四项硬禁令逐条证明

| 约束 | 提案落实 | 审查依据 |
|---|---|---|
| 无渐变 | 背景#FFFFFF/冷灰#F5F7FA，分隔线#D5DAE1，文字#202833，主动作纯色#175CD3 | 不用gradient、光晕、blur遮罩、渐变文字；线框无此装饰；后续截图和CSS扫描复核 |
| 非暖黄主色 | 石墨/白/冷灰 + 克制蓝主按钮；错误暗红#B42318，警告用文字/描边 | 主要按钮不使用暖黄/琥珀；主按钮白字对比约6.0:1，需在正式实现复测 |
| 无AI风 | 真实文件行、实际任务、业务状态，无Hero巨标题、霓虹、玻璃、发光、浮球、假卡片或装饰动画 | 画布优先，只有业务动作；边角建议4px；不引入AI图标/营销术语 |
| 无无意义容器嵌套 | 页面→Section grid→文件行/操作视口/请求内容；每列靠分隔线，表单字段不套内卡片 | 边界目的逐项：Section区分业务；画布框限定平移缩放；上传队列表示独立进度；抽屉只用于当前编辑；无重复page-card/card/card |

这是设计层自检，不能替代正式实现后的截图审查。P0-0页面只有原生排版文字，未把此配色或布局应用为产品UI。

## 具体待决策事项与推荐

| ID | 决策 | 推荐 / 权衡 |
|---|---|---|
| UI-01 | 桌面三列+窄屏单目标，或全屏编辑+抽屉 | 推荐三列主方案，窄屏用全宽目标；减少资料/请求来回切换 |
| UI-02 | 客户数值/拍照/无法测量是否同级可见 | 推荐三个直接选项；不把“无法”隐藏在菜单 |
| UI-03 | 视觉语言 | 推荐冷灰/白/石墨+纯蓝，系统中文字体；无外部字体请求 |
| UI-04 | 任务submitted后客户能否立即追加修改 | 推荐先等待审核，需重测再提交；若要主动纠错需追加事件，不覆盖旧回复 |
| UI-05 | 客户归档访问 | 推荐可读历史与下载，禁止新上传/回复；恢复由Owner操作 |
| SEC-01 | 链接有效期/会话/去令牌地址 | 推荐链接30天、会话24h，每次核撤销；静态`/s/session`清理明文URL |
| SEC-02 | 私有下载方式 | 推荐受控代理；若成本用60秒签名须接受残留窗口，签名上传本身有2h窗口 |
| FILE-01 | 初始格式/配额 | 推荐架构文档的保守上限；HEIC/视频先禁用；实测后调整需批准 |
| FILE-02 | 客户照片下载原件或标准图 | 推荐标准图（去敏EXIF），Owner另有原件下载；影响客户保真需求须确认 |
| OPS-01 | 大陆网络与Canvas试验门槛 | 大陆网络经用户决定延至UI可操作后、P0最终验收前；当前不阻断P0-0。独立Canvas结果见10，未实测阈值仍非承诺SLA |

批准可按UI-01～05整批确认，无需逐按钮审批；安全/配额/架构决策另批确认。**当前所有项目均pending，没有用户批准记录。** 本次提交后等待明确意见；批准也不自动授权跨阶段实施，需另行启动对应P0任务。
