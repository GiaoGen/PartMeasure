## 已完成

| 改动 | 原因和边界 |
| --- | --- |
| IndexedDB只保存不可变图片字节和淘汰元数据 | 页面刷新可继续使用已下载图片；不保存Cookie、密码、会话凭据、可读清单或回复历史 |
| 有本地内容时，先取得新鲜图片可读清单，再读取该分区的本地Blob | 每批最多30个文件，正常Auth/限流/RLS与项目/分享撤销检查；只返回有权文件，一个隐藏文件不阻塞同批其他照片。清单不是下载凭证，不支持离线绕过核权 |
| 按角色、项目、身份及Guest会话代次生成不透明分区，图片按SHA-256复用 | Owner、Guest和不同账号的旧内容不能混用；首次正常受控预览响应附带版本/分区，可直接写入缓存，不多跑一次清单核权 |
| 96MiB / 48项 / 最长24小时，LRU淘汰；单项最多32MiB持久化 | 本地读取验证版本、大小、SHA-256。容量不足、浏览器禁用存储或超时自动回退网络；大图仍可正常读取，只是不持久保存 |
| 退出/账号切换/401清理，文件隐藏/分享撤销精准清理，多标签同步 | 迟到请求或异步写盘不能重新放回已清理数据；普通离页/刷新只清页面内存，不再被当作注销而删除持久字节。清单失败时不展示旧私有图片 |
| 有限保留最近一张闲置标准图的解码结果，最长20秒 | 来回开同图可以省一次解码；跨标签失效和账号切换同时清理解码对象/待解码请求。保留标准图尺寸校验，不用缩略图代替正式编辑坐标 |
| 上传最多两份在途，处理请求一次一份 | 下一张传输可与上一张处理重叠；仍遵守服务端项目4份、同上传者2份预留上限。自动申请名额按现有10次/分钟限制节流，最多20个排队文件 |
| 上传区分校验、准备名额、传输、等待处理、已完成 | 用“已确认上传”的独立标记决定是否跳过重传，不再根据进度四舍五入到100%推断成功；Busy/Active只做有界语义重试，未知写入结果不无限重试。取消/换账号终止哈希和传输监听 |
| 私有下载全局最多2路，缓冲和拼装预留总额256MiB | 分段从4MiB改为8MiB，仍逐段核权、校验206/Content-Range/准确长度；单段90秒、一次操作最多5分钟。保留30秒失败片段用于重试，完成后Blob URL最多15秒释放；退出/离开及时释放 |
| 修正服务端小缩略图缓存对内容hash路径的识别 | 第二阶段补建的缩略图也能走已核权的服务端字节缓存，保留每次先核权的约束 |
| 提供构建可追溯的非生产入口 | 原 `partmeasure-staging` 项目的preview，函数东京hnd1，仍连接原隔离Supabase；健康接口公开构建号用于核对，不将健康存活等同数据库就绪 |

未增加数据库schema、收费资源、代理层、Docker或常驻Worker；未修改已有标准图、归一化坐标、回复历史、私有桶、RLS或业务状态流。新资产继续如实标记format-only-v2，不宣称病毒扫描。

- 刷新仍需加载页面/元数据并新鲜核权，**不是零请求、零等待**。超过32MiB的单张图片、超容量淘汰、超过24小时、浏览器限制存储、换账号/新Guest会话都可能重新传图。
- 24小时是缓存的逻辑复用期限：到期后不再复用，条目在后续访问/写入/清理时淘汰；浏览器关闭期间无法执行定时物理删除。程序清理不能承诺法证级擦除，也无法召回用户已保存的文件。持久字节不赋予离线访问权限。
- 下载预算只核算应用持有的编码缓冲与拼装预留，不是浏览器、GC、Konva或操作系统的硬内存上限。
